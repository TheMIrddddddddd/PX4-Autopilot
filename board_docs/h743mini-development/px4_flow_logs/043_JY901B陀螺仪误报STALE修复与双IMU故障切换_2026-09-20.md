# 043 JY901B 陀螺仪误报 STALE 修复与双 IMU 故障切换

时间：2026-09-20

## 1. 本轮目标

记录 `voted_sensors_update.cpp` 中针对 JY901B 陀螺仪的最小修改，并说明：

1. 修改前发生了什么现象。
2. 原始 PX4 代码为什么会把 JY901B 判定为 `STALE`。
3. 修改前后代码行为的差异。
4. 为什么只调整 JY901B 陀螺仪，而不修改 ICM42688P、加速度计或整体投票器。
5. 修改后双 IMU 主备选择、故障切换和固件烧录验证结果。

本日志只针对 IMU 投票器修改。之前为区分 Ready to Arm 与 Not Ready 而临时修改的 `Commander.cpp` LED 逻辑已经回退，不属于本次代码提交。

## 2. 当前硬件和 IMU 角色

| 设备 | 接口 | 当前角色 | PX4 状态 |
|---|---|---|---|
| ICM42688P | SPI2 | 主 IMU | 加速度计/陀螺仪优先级 75 |
| JY901B | UART4 `/dev/ttyS3` | 备 IMU | 加速度计/陀螺仪优先级 50 |

当前配置目标：

```text
SENS_IMU_MODE = 1
ICM42688P     = primary
JY901B        = backup
```

JY901B 的板级坐标方向已经通过实物 A/B 对比确认使用 `SENS_JY901_ROT=0`；本次没有修改坐标变换和旋转参数。

## 3. 修改前的实际现象

### 3.1 串口通信本身正常

静止零漂测试期间，JY901B 驱动状态显示：

- 加速度、陀螺仪、磁力计和气压数据持续发布。
- 读错误为 0。
- 校验错误为 0。
- 最近一帧时间正常，数据时间戳持续更新。
- 驱动频率约为 140–200 Hz，取决于当时的启动配置和统计窗口。

因此当时没有证据表明 UART4、DMA、帧解析或 JY901B 模块已经掉线。

### 3.2 DataValidator 错误地报告 STALE

飞控静止时，JY901B 陀螺仪长期输出：

```text
[0, 0, 0]
```

随后 `sensors status` 中出现类似状态：

```text
sensor #0: ICM42688P  state: OK
sensor #1: JY901B     state: STALE
```

这会产生两个问题：

1. JY901B 虽然持续有带时间戳的新数据，却被投票器认为不健康。
2. JY901B 不能稳定地作为 ICM42688P 的有效备份传感器参与投票和故障切换。

现象的关键矛盾是：

```text
数据流仍在更新       = 通信正常
数据值连续相同为零   = 被通用 DataValidator 当成 STALE
```

## 4. 原始代码与修改后代码对比

### 4.1 修改前的原始代码

在 `imuPoll()` 中，原始 PX4 代码只更新陀螺仪设备 ID：

```cpp
_accel_device_id[uorb_index] = imu_report.accel_device_id;
_gyro_device_id[uorb_index] = imu_report.gyro_device_id;
```

陀螺仪投票器沿用 `DataValidator` 的默认连续相同值阈值：

```cpp
DataValidator::VALUE_EQUAL_COUNT_DEFAULT = 100
```

也就是连续收到超过 100 次完全相同的数值后，投票器设置：

```text
ERROR_FLAG_STALE_DATA
```

在 JY901B 约 140–200 Hz 的输出频率下，静止零输出很快就会触发这个条件。

### 4.2 修改后的代码

当前修改增加了设备类型识别：

```cpp
#include <drivers/drv_sensor.h>
#include <lib/drivers/device/Device.hpp>
```

并在陀螺仪设备 ID 变化时设置对应的连续相同值阈值：

```cpp
if (_gyro_device_id[uorb_index] != imu_report.gyro_device_id) {
	_gyro_device_id[uorb_index] = imu_report.gyro_device_id;

	device::Device::DeviceId device_id{};
	device_id.devid = imu_report.gyro_device_id;

	const uint32_t equal_value_threshold =
		(device_id.devid_s.devtype == DRV_IMU_DEVTYPE_JY901B) ?
		UINT32_MAX : DataValidator::VALUE_EQUAL_COUNT_DEFAULT;

	_gyro.voter.set_equal_value_threshold(uorb_index, equal_value_threshold);
}
```

修改后的行为：

| 传感器 | 连续相同值阈值 | 超时判断 | 目的 |
|---|---:|---|---|
| ICM42688P 陀螺仪 | 100，保持原逻辑 | 保留 | 不改变主 IMU 的原有保护机制 |
| JY901B 陀螺仪 | `UINT32_MAX`，实际关闭该值相同判据 | 保留默认超时 | 允许静止时合法的零速率输出 |
| 两类加速度计 | 未修改 | 未修改 | 不扩大本次改动范围 |

设备 ID 变化时才重新设置阈值，避免在每个 IMU 样本上重复配置投票器。

## 5. 为什么要这样修改

### 5.1 不是关闭所有故障保护

本次没有直接把 JY901B 标记为永久健康，也没有删除 DataValidator。修改只针对一种已确认的误判来源：

```text
合法静止零输出 + 时间戳持续更新
```

原有的无数据和超时检测仍然保留。`DataValidator` 默认超时为 `40000 us`，即约 40 ms：

```cpp
uint32_t _timeout_interval{40000};
```

如果 JY901B 真正停止输出，时间戳不再更新，仍会触发：

```text
ERROR_FLAG_TIMEOUT
```

投票器仍可以据此把 JY901B 判为故障并切换到其他 IMU。

### 5.2 不能把 ICM42688P 一起改掉

ICM42688P 是当前主 IMU，输出频率高、有效动态范围和更新行为不同。若直接把所有陀螺仪的连续相同值检测都关闭，会降低主 IMU 对“数据冻结但时间戳仍变化”问题的检测能力。

因此本次修改通过设备类型限定在：

```text
DRV_IMU_DEVTYPE_JY901B
```

而不是修改全局默认阈值。

### 5.3 修改触发原因

本次修改是由以下证据链触发的：

1. 30 分钟静止观察中，JY901B 陀螺仪长期输出零。
2. `jy901b status` 显示读错误、校验错误和超时没有异常。
3. JY901B 的时间戳和发布频率仍然正常。
4. 只有通用 DataValidator 的“连续相同数值”状态变成 `STALE`。
5. 停止 JY901B 数据流时，仍然需要保留真正的超时故障检测。

所以最小、针对性的修复是：只为 JY901B 陀螺仪关闭“值不变”判据，保留时间戳超时判据。

- 固件擦除完成。
- 固件写入完成。
- Bootloader 校验 100% 通过。
- 飞控自动重启。

当前生成固件：

```text
build/gjl_h743mini_default/gjl_h743mini_default.px4
```

### 6.2 运行时 MAVLink 基线检查

烧录后通过 USB MAVLink 读取到：

- `HIGHRES_IMU` 持续输出。
- `ATTITUDE` 持续输出。
- `ATTITUDE_QUATERNION` 持续输出。
- 心跳状态为 `STANDBY`，未解锁。
- 未出现新的 IMU 启动错误或严重故障信息。
- GPS 无星时只有预期的 `Preflight: GPS fix too low` 警告。

这说明修改后的固件已经正常启动，且没有破坏 MAVLink、姿态或 IMU 主链路。

### 6.3 双 IMU 故障切换测试

在拆桨、飞控静止和电机动力隔离条件下，已完成以下流程：

```sh
# ICM42688P 和 JY901B 均正常运行时
sensors status

# 停止主 IMU
icm42688p stop
sleep 1
sensors status

# 恢复主 IMU
icm42688p -R 0 -s -f 2000 start
sleep 1
sensors status
```

期望并已观察到的逻辑是：

1. 正常时 ICM42688P 为 selected gyro/accel。
2. ICM42688P 停止后，JY901B 不再因为静止零输出被误报 `STALE`，可以成为有效候选。
3. ICM42688P 恢复后，因优先级更高而重新成为主 IMU。

### 6.4 断线判据的边界

本次修改只修复“合法零输出被误报 `STALE`”。如果 JY901B 完全停止发布，应该由时间戳超时判据负责识别；如果模块仍然持续发送错误但时间戳持续更新，则仍需要依靠错误计数、动态一致性和后续有效分辨率测试进一步判断。

- JY901B UART4 数据链路正常。

- JY901B 加速度计和两颗 IMU 的其他投票逻辑未修改。
- JY901B 真正停止数据流时的超时保护仍保留。
- 双 IMU 主备切换和恢复路径已完成现场验证。
