# 018 跑通 PX4 bootloader upload

时间：2026-06-27 18:40:11

## 概念
本次跑通的是 PX4 bootloader upload 链路：

```text
电脑 px_uploader.py
  -> USB CDC /dev/ttyACM0
  -> PX4 bootloader
  -> 擦除主程序区域
  -> 写入 gjl_h743mini_default.px4 内的主程序镜像
  -> 校验
  -> 重启
```

它和 ST-Link 烧录不同：

- ST-Link 可以直接写 bootloader 和主程序。
- PX4 bootloader upload 主要用于更新主程序，不用于救 bootloader。

## 代码/流程
执行命令：

```bash
make gjl_h743mini_default upload
```

关键输出：

```text
Loaded firmware for board id: 56,0 size: 1855336 bytes (94.37%), waiting for the bootloader...
Found board id: 56,0 bootloader version: 5
Erase
Program
Verify
Rebooting. Elapsed Time 25.642
Built target upload
```

本次确认：

- `.px4` 固件包 `board_id = 56`。
- bootloader 侧 `BOARD_TYPE = 56`。
- board id 匹配。
- PX4 bootloader upload 已经可以完成主程序更新。

## 常见坑
最初 `make upload` 一直停在：

```text
waiting for the bootloader...
```

排查过程发现：

- QGroundControl 曾占用 `/dev/ttyACM0`，需要先关闭 QGC。
- 后续串口未被占用，但 uploader 仍然抓不到 bootloader。
- 根因是电脑端 Python 没有安装 `pyserial`。
- 仓库内存在 `Tools/serial/` 目录，导致 `import serial` 看似成功，但不是 pyserial，内部没有 `serial.Serial`。
- `px_uploader.py` 在内部反复创建 uploader 失败，外部表现就是一直等待 bootloader。

解决命令：

```bash
python3 -m pip install --user pyserial
```

## 调试方法
检查串口是否被占用：

```bash
fuser -v /dev/ttyACM0
```

检查 PX4 USB 设备：

```bash
ls -l /dev/serial/by-id/
```

检查 pyserial：

```bash
python3 - <<'PY'
import serial
print(serial.__file__)
print(hasattr(serial, "Serial"))
PY
```

期望结果：

```text
.../site-packages/serial/__init__.py
True
```

## 复盘要点
`waiting for the bootloader...` 不一定是板子没进 bootloader。它可能是：

- QGC 或串口助手占用 USB CDC。
- uploader 的端口匹配没匹配到当前设备。
- Python 端缺少 `pyserial`，导致 uploader 无法真正打开串口。

本次最终证明：当前板子的 PX4 bootloader、`.px4` 固件包、board id 和 USB CDC 链路都可以工作。
