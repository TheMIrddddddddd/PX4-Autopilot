# 020 TF 卡读取问题调试复盘

时间：2026-06-29

## 任务背景

本次调试对象是自定义 H743mini 飞控板：

```text
硬件平台：STM32H743IIT6 小系统板 / GJL_H743MINI
PX4 分支：h743mini-v1.13.3
PX4 版本：1.13.3
构建目标：gjl_h743mini_default
启动系统：NuttX 11.0.0
TF 卡设备：/dev/mmcsd0
TF 卡挂载点：/fs/microsd
```

最初目标是让 PX4 上电后自动挂载 TF 卡，并让参数、dataman、logger 等模块正常使用 `/fs/microsd`。

当前确认到的核心现象是：

- 完全断电后重新上电，TF 卡可以识别并挂载为 `/fs/microsd type vfat`。
- 在 NSH 中输入 `reboot`，或者按板载复位键重启后，TF 卡无法再次识别。
- 软复位失败后，`mount -t vfat /dev/mmcsd0 /fs/microsd` 会报 `Out of memory`，但这不是普通内存不足。
- 当前开发阶段的可用策略是：调试 TF 卡、参数保存、日志和 dataman 时，优先使用完全断电启动，不依赖 `reboot` 或复位键。

本轮只记录调试复盘，不修改主 `px4_flow.md`，不清理当前源码中的临时调试代码。

## 概念

这次问题不能只看 `mount failed: Out of memory` 字面意思。

PX4/NuttX 里 TF 卡启动大致分成几层：

```text
板级 SDIO 初始化
  -> sdio_initialize()
  -> mmcsd_slotinitialize()
  -> sdio_mediachange()
  -> MMCSD 识别卡类型和容量
  -> 生成 /dev/mmcsd0 块设备 geometry
  -> mount -t vfat /dev/mmcsd0 /fs/microsd
  -> param/dataman/logger 使用 /fs/microsd
```

FAT 层要挂载成功，必须先从块设备拿到有效几何信息：

```text
geo_sectorsize = 512
geo_nsectors   = 有效扇区数量
```

失败时看到的是：

```text
sectorsize=0
nsectors=0
fat_io_alloc request=0
mount failed: Out of memory
```

这里的 `Out of memory` 是后续错误表现，不是根因。真正的问题是前面的 MMCSD 卡识别失败，导致块设备没有得到有效的 `blocksize/nblocks`。

### 已确认的 SDMMC1 引脚

根据当前板载 TF 卡连接，实际使用的是 STM32H743 的 SDMMC1：

```text
SDIO_D0   PC8
SDIO_D1   PC9
SDIO_D2   PC10
SDIO_D3   PC11
SDIO_CLK  PC12
SDIO_CMD  PD2
```

`boards/gjl/h743mini/nuttx-config/nsh/defconfig` 当前应保持：

```text
CONFIG_STM32H7_SDMMC1=y
# CONFIG_STM32H7_SDMMC2 is not set
```

### 已规避的 UART5 冲突

排查中发现 UART5 与 SDMMC1 引脚有冲突：

```text
UART5_RX   PD2   与 SDIO_CMD 冲突
UART5_TX   PC12  与 SDIO_CLK 冲突
UART5_RTS  PC8   与 SDIO_D0 冲突
UART5_CTS  PC9   与 SDIO_D1 冲突
```

因此当前已经关闭 UART5 及 TEL2：

```text
boards/gjl/h743mini/nuttx-config/nsh/defconfig
  # CONFIG_STM32H7_UART5 is not set
  # CONFIG_UART5_IFLOWCONTROL is not set
  # CONFIG_UART5_OFLOWCONTROL is not set
  # CONFIG_UART5_RXDMA is not set
  # CONFIG_UART5_TXDMA is not set

boards/gjl/h743mini/default.px4board
  # CONFIG_BOARD_SERIAL_TEL2 is not set
```

这一步是必要的，否则 TF 卡 CMD/CLK/D0/D1 可能被 UART5 抢占。

### 仍发现的 PC10/PC11 冲突

源码中仍有一处需要后续清理：

```text
boards/gjl/h743mini/src/board_config.h
  GPIO_VDD_5V_HIPOWER_nEN   /* PC10 */
  GPIO_VDD_5V_HIPOWER_nOC   /* PC11 */
```

但当前板载 TF 卡使用：

```text
SDIO_D2   PC10
SDIO_D3   PC11
```

所以 `GPIO_VDD_5V_HIPOWER_nEN/_nOC` 与 TF 卡 D2/D3 有资源冲突。当前文档只记录这个风险，后续应单独清理 board_config 中不符合本板硬件的 V6C 遗留电源控制定义。

### 当前保留的软件尝试

`boards/gjl/h743mini/src/sdio.c` 中已经加入初始延迟：

```text
#define MMCSD_INITIAL_DELAY_US    1000000

usleep(MMCSD_INITIAL_DELAY_US);
sdio_mediachange(sdio_dev, true);
```

这个 1 秒延迟可以作为冷启动稳定性保护保留，但它不能从根本上解决复位键或 NSH `reboot` 后 TF 卡不重新 ready 的问题。

为了定位问题，曾在 NuttX 子模块中加入临时调试输出：

## 排查过程

### 1. 从参数保存失败开始

最早看到的是 `param save` 失败。因为 PX4 默认参数文件路径在 `/fs/microsd/params`，所以第一判断是 TF 卡没有成功挂载或不可写。

使用：

```sh
mount
ls /fs/microsd
echo ok > /fs/microsd/write_test.txt
cat /fs/microsd/write_test.txt
```

确认了失败时 `/fs/microsd` 并不是可写 vfat 文件系统。

### 2. 手动 mount 暴露 `Out of memory`

手动执行：

```sh
mkdir /fs/microsd
mount -t vfat /dev/mmcsd0 /fs/microsd
```

失败输出：

```text
nsh: mount: mount failed: Out of memory
```

当时一度怀疑是 NuttX 内存、DMA pool 或 FAT sector buffer 不够。

### 3. 用 free 排除普通内存不足

失败时 `free` 显示普通堆仍有较大空间：

```text
                   total       used       free    largest  nused  nfree
        Umem:     953760     182544     771216     460480    629     29
        Prog:    2097184    1900928     196256     110688  59404   6133
```

后来 DMA 统计也显示：

```text
DMA Memory: 16384 total, 0 used 0 peak
```

这排除了“FAT 挂载需要 DMA buffer 但 DMA pool 不够”的假设。`DMA Memory peak=0` 说明这条失败路径没有真正用到 DMA 池。

### 4. 在 mount/FAT 层加日志

加入 `[mount-debug]` 与 `[fat-debug]` 后，看到失败时：

```text
[fat-debug] geometry ret=0 available=1 write=1 sectorsize=0 nsectors=0
[fat-debug] fat_io_alloc request=0
[fat-debug] fat_io_alloc failed request=0
```

这一步把问题从“FAT 内存不足”前移到“块设备 geometry 不正确”。

### 5. 在 MMCSD 层加日志

继续在 `mmcsd_sdio.c` 中打印 `CMD8`、`ACMD41`、`CSD`、`blocksize/nblocks`。

冷启动成功时：

```text
ACMD41 response=0xc0ff8000
cardidentify success
CSD decoded blocksize=512 nblocks=65536000
```

软复位失败时：

```text
ACMD41 response=0x40ff8000
cardidentify failed elapsed=1000
blocksize=0 nblocks=0
```

这一步确认失败发生在 SD 卡识别阶段，不是 FAT32 文件系统本身损坏，也不是 `/fs/microsd` 目录问题。

### 6. 对比冷启动和软复位

最终稳定复现：

```text
完全断电 -> 上电启动 -> TF 卡可识别，可挂载
NSH reboot -> 软重启 -> TF 卡不可识别
板载复位键 -> MCU reset -> TF 卡不可识别
拔插 TF 卡或完全断电 -> 状态恢复
```

这个对比说明 TF 卡本体或 TF 卡供电状态没有随 MCU 复位一起复位。

## 已尝试的软件处理

### 板级启动延迟

已在 `boards/gjl/h743mini/src/sdio.c` 加入 1 秒初始延迟：

```text
usleep(1000000);
sdio_mediachange(sdio_dev, true);
```

效果：

- 对冷启动有稳定性帮助。
- 对软复位后卡停在 `0x40ff8000` 的情况没有根治效果。

### MMCSD 内部 retry

曾尝试在 `mmcsd_probe()` 内部失败后重新执行：

```text
mmcsd_removed(priv)
mmcsd_cardidentify(priv)
```

并加入多次 retry 和延迟。

效果：

- 可以证明重复识别仍失败。
- 软复位后仍停留在 `ACMD41 response=0x40ff8000`。

### SDIO_RESET 尝试

进一步尝试过：

```text
SDIO_RESET(priv->dev)
```

再重新 `mmcsd_cardidentify()`。

效果：

- MCU 侧 SDIO 控制器可以重置。
- 但 TF 卡供电没有断开，卡本体状态没有被强制重新上电。
- 因此软复位后仍可能失败。

## 当前结论与修复方向

### 已解决 / 已验证

冷启动场景已经验证可用：

```text
完全断电 -> 上电 -> ACMD41 进入 0xc0ff8000 -> cardidentify success
  -> sectorsize=512 -> mount 成功 -> /fs/microsd type vfat
```

因此：

- TF 卡本体不是完全坏的。
- SDMMC1 引脚方向基本正确。
- FAT32 文件系统不是当前主矛盾。
- `/dev/mmcsd0` 能够在成功场景提供有效 geometry。

### 未根治

软复位场景没有根治：

```text
NSH reboot / 板载 reset
  -> TF 卡未被断电
  -> ACMD41 长时间停在 0x40ff8000
  -> blocksize=0 nblocks=0
  -> mount failed: Out of memory
```

这说明问题很可能在 TF 卡电源复位路径，而不是单纯软件延时。

### 当前可用方式

开发阶段建议：

```text
需要验证 TF 卡、参数、dataman、logger
  -> 完全断开板子供电
  -> 等待 TF 卡和 MCU 都掉电
  -> 重新上电
  -> 进入 NSH 后先 mount / dmesg 验证
```

暂时不要把 `reboot` 或板载复位键后的 TF 卡状态当成可靠状态。

### 长期硬件修复

当前小系统板 TF 卡 VDD 直接接公共 `3.3V`，没有独立可控电源。软复位时 MCU 重启了，但 TF 卡没有掉电，因此卡内部状态可能停在上一次会话后的异常状态。

长期硬件方案：

```text
公共 3.3V
  -> load switch 或 P-MOS
  -> VDD_3V3_SD_CARD
  -> TF 卡 VDD

MCU GPIO
  -> 控制 TF_PWR_EN
```

启动流程配套改为：

```text
TF_PWR_EN = 0
delay
TF_PWR_EN = 1
delay
SDMMC init
mmcsd_slotinitialize
sdio_mediachange
mount /fs/microsd
```

### 纯软件方案的限制

纯软件最多改善 NSH `reboot` 场景，因为软件有机会在重启前执行关卡流程。

但板载复位键通常直接复位 MCU，不会让 PX4/NuttX 先执行：

```text
unmount
SDIO reset
TF power off
delay
```

所以如果硬件上没有 TF 卡独立电源开关，复位键问题很难靠软件彻底解决。

## 与 FMUv6C 的对比

参考 FMUv6C / Pixhawk 6C 类设计时，需要注意原板不是简单把 TF 卡 VDD 直接挂公共 3.3V。

对比结论：

- 原 FMUv6C 设计里有独立的 `VDD_3V3_SD_CARD`。
- 参考资料中还能看到 SD 卡上电延时相关设计说明，例如 `Install C10 for SD power up delay`。
- 当前 H743mini 小系统板 TF VDD 直接接公共 `3.3V`，缺少“让卡本体重新上电”的硬件手段。

这解释了为什么完全断电有效，而 `reboot` / reset 无效。

## 常见坑

### 1. 不要被 `Out of memory` 带偏

这次 `Out of memory` 不是普通 RAM 不够。真正原因是：

```text
MMCSD 未识别卡容量
  -> geometry sectorsize=0
  -> FAT 申请 0 字节 sector buffer
  -> 返回 -ENOMEM
  -> mount 显示 Out of memory
```

### 2. `/dev/mmcsd0` 存在不等于卡可用

失败时 `/dev/mmcsd0` 仍可能存在：

```text
nsh> ls /dev
/dev:
 ...
 mmcsd0
 ...
```

但 geometry 可能仍是：

```text
blocksize=0
nblocks=0
```

所以必须看 `dmesg` 中的 `CSD decoded`、`sectorsize=512`、`nblocks`。

### 3. `mount` 里没有 `/fs/microsd` 才是关键

只看 `/fs/microsd` 目录是否存在不够。目录可以手动 `mkdir` 出来，但真正成功要看：

```text
nsh> mount
  /fs/microsd type vfat
```

### 4. DMA pool 不是这次根因

虽然 `BOARD_DMA_ALLOC_POOL_SIZE` 从 `5120` 调到 `16384` 可以作为板级余量保留，但本次失败链路里：

```text
DMA Memory peak=0
```

所以不能把这次软复位失败归因于 DMA 池太小。

### 5. UART5 引脚冲突必须保持关闭

UART5 会占用 SDMMC1 的关键引脚，尤其是 `PD2` 和 `PC12`：

```text
PD2   SDIO_CMD
PC12  SDIO_CLK
```

如果后续恢复 UART5/TEL2，很可能再次破坏 TF 卡链路。

```text
CSD decoded blocksize=512
geometry ret=0 available=1 write=1 sectorsize=512
/fs/microsd type vfat
```

### 判断软复位是否失败

失败时典型组合是：

```text
ACMD41 response=0x40ff8000
cardidentify failed
blocksize=0 nblocks=0
geometry ret=0 available=1 write=1 sectorsize=0 nsectors=0
mount failed: Out of memory
```

### 下一次继续调试建议

如果继续做软件侧验证，可以按这个顺序：

```text
1. 完全断电启动，确认冷启动仍可挂载。
2. NSH 中记录 dmesg 和 mount。
3. 执行 reboot。
4. 软复位后记录 dmesg 和 mount。
5. 对比 ACMD41、cardidentify、blocksize/nblocks。
6. 如果加硬件电源开关，再验证 TF_PWR_EN 断电重上电是否能恢复软复位。
```

如果继续做硬件侧验证，可以重点测：

```text
1. 冷启动时 TF VDD 上电波形。
2. NSH reboot 时 TF VDD 是否始终保持 3.3V。
3. 板载 reset 键按下时 TF VDD 是否始终保持 3.3V。
4. CMD/CLK/D0-D3 在 reset 前后是否有异常电平保持。
5. 加临时断电或拔插 TF 卡后，卡是否立即恢复可识别。
```

## 复盘要点

本次最重要的修正是：不要把最外层错误当根因。

最开始看到的是：

```text
param save failed
mount failed: Out of memory
```

但真正证据链是：

```text
软复位后 TF 卡没有真正掉电
  -> ACMD41 只能到 0x40ff8000，不能到 0xc0ff8000
  -> cardidentify failed
  -> CSD 没读到
  -> blocksize/nblocks 仍为 0
  -> FAT 层 geometry sectorsize=0
  -> mount 报 Out of memory
```

因此当前结论要分清：

- 已验证：完全断电启动后 TF 卡可挂载，参数和 dataman 可以使用 `/fs/microsd`。
- 未根治：NSH `reboot` 或板载复位键后 TF 卡仍不 ready。
- 当前可用方式：调试阶段用完全断电启动。
- 长期修复方向：给 TF 卡 VDD 增加可控电源，让 MCU 能主动重启 TF 卡本体。

这次也说明，移植 FMUv6C 这类板级代码时不能只复制软件配置，还要检查原硬件设计中隐藏的电源域、上电延时、电源开关和复位路径。

## 下一阶段任务和目标
