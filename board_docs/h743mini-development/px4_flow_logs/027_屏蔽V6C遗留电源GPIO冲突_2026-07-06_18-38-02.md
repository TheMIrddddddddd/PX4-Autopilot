## 任务背景

当前 H743mini 已完成 EEPROM 与 GD25Q128 存储适配，并已规划后续飞控传感器：

- `ICM42688P`：主 IMU。
- `GPS + IST8310`：GPS 与主磁力计。
- `JY901B`：副 IMU / 气压计 / 姿态参考。

由于主 IMU 硬件暂未到位，本轮先处理板级遗留问题。

从 FMU-v6C 继承来的部分电源 GPIO 与当前真实外设冲突：

| 引脚 | V6C 遗留用途 | H743mini 当前/规划用途 |
|---|---|---|
| `PB2` | `GPIO_VDD_3V3_SENSORS_EN`，传感器 3.3V 电源使能 | GD25Q128 `QSPI_CLK` |
| `PC10` | `GPIO_VDD_5V_HIPOWER_nEN`，高功率 5V 使能 | TF 卡 `SDMMC1_D2` |
| `PC11` | `GPIO_VDD_5V_HIPOWER_nOC`，高功率 5V 过流检测 | TF 卡 `SDMMC1_D3` |
| `PA15` | `GPIO_nPOWER_IN_A` / `Brick1 valid` | 后续 `TIM2_CH1 / M1 PWM` |

## 概念

### 为什么不能直接删除

这些宏来自 FMU-v6C 的完整电源管理设计。直接删除会丢失“这个脚以前为什么存在”的上下文，也可能让后续查阅 V6C 差异时更难对照。

本轮采用的方式是：

```text
保留遗留宏和注释
 -> 不再初始化冲突引脚
 -> 不再读写冲突引脚
 -> 对没有真实电源检测电路的状态给固定安全值
```

### 屏蔽和释放的区别

本轮只是“屏蔽遗留电源用途”，不是立刻完成全部新功能。

- `PB2` 已释放给 QSPI，但 QSPI 之前已经验证通过。
- `PC10/PC11` 已释放给 TF 卡 SDMMC1，但 TF 卡仍以完全断电冷启动验证为准。
- `PA15` 已不再被 power valid 读取，后续真正用于 PWM 还需要修改 `timer_config.cpp` 和 NuttX TIM2 配置。

## 本轮修改内容

### 1. 注释说明 V6C 遗留电源 GPIO

在 `boards/gjl/h743mini/src/board_config.h` 的电源 GPIO 区域补充说明：

```text
H743mini does not carry over the full FMUv6C power-switch circuit.
```

并明确记录：

- `PA15` 保留给 `TIM2_CH1 / M1 PWM`。
- `PC10/PC11` 属于 `SDMMC1 D2/D3`。
- `PB2` 属于 GD25Q128 `QSPI_CLK`。

### 2. 屏蔽 high-power 5V 和 sensors 3V3 控制函数

把：

```c
VDD_5V_HIPOWER_EN(on_true)
VDD_3V3_SENSORS_EN(on_true)
```

改成 no-op：

```c
do { (void)(on_true); } while (0)
```

作用：

- 后续即使有代码调用这些宏，也不会再驱动 `PC10` 或 `PB2`。
- 同时修掉了 `VDD_3V3_SENSORS_EN()` 原本引用不存在的 `GPIO_VDD_3V3_SENSORS4_EN` 的遗留问题。

### 3. 固定电源状态读取

把 `BOARD_ADC_BRICK1_VALID` 改为固定有效：

```c
#define BOARD_ADC_BRICK1_VALID  (1)
```

原因：

- 当前 H743mini 没有照搬 V6C 的 Brick1 valid 电路。
- `PA15` 后续规划给 `TIM2_CH1 / M1 PWM`，不应继续读作电源有效输入。

把 `BOARD_ADC_HIPOWER_5V_OC` 改为固定无过流：

```c
#define BOARD_ADC_HIPOWER_5V_OC (0)
```

原因：

- 当前没有 V6C high-power 5V 过流检测电路。
- `PC11` 是 TF 卡 `SDMMC1_D3`。

### 4. 从 PX4_GPIO_INIT_LIST 中屏蔽冲突脚

从 `PX4_GPIO_INIT_LIST` 中移除：

```text
GPIO_nPOWER_IN_A
GPIO_VDD_5V_HIPOWER_nEN
GPIO_VDD_5V_HIPOWER_nOC
GPIO_VDD_3V3_SENSORS_EN
```

同时增加注释说明这些脚不再作为 V6C 遗留电源脚初始化。

## 修改流程

1. 读取 `board_config.h` 中电源 GPIO 定义、状态读取宏和 `PX4_GPIO_INIT_LIST`。
2. 对照 `board.h` 中当前真实外设占用：
   - `PB2 = QSPI_CLK`
   - `PC10/PC11 = SDMMC1 D2/D3`
   - `PA15 = 后续 TIM2_CH1 / M1 PWM`
3. 按用户要求选择“屏蔽 + 注释”，不直接删除旧定义。
4. 修改 no-op 宏和固定状态值。
5. 从 `PX4_GPIO_INIT_LIST` 移除冲突脚，避免启动阶段错误初始化。
6. 执行 `git diff --check`。
7. 执行 `make gjl_h743mini_default` 编译验证。

## 当前结论

- `PB2` 已不再作为 `GPIO_VDD_3V3_SENSORS_EN` 初始化或驱动，保留给 GD25Q128 `QSPI_CLK`。
- `PC10/PC11` 已不再作为 `VDD_5V_HIPOWER` 使能/过流检测初始化或读写，保留给 TF 卡 `SDMMC1 D2/D3`。
- `PA15` 已不再作为 `Brick1 valid` 读取，后续可以释放给 `TIM2_CH1 / M1 PWM`。
- 旧宏和上下文仍保留在源码中，便于后续理解这些定义来自 V6C 电源管理设计。
- 当前修改已通过 `gjl_h743mini_default` 编译验证。

## 常见坑

- 不要把“宏还在文件里”误认为它仍然参与引脚初始化；关键要看是否进入 `PX4_GPIO_INIT_LIST`，以及是否仍被读写宏驱动。
- 不要把 `PB2` 重新规划给任何普通 GPIO；它已经是 QSPI 时钟。
- 不要把 `PC10/PC11` 重新规划给电源控制；它们属于 TF 卡 SDMMC1。
- `PA15` 只是从 power-valid 逻辑释放出来，后续要真正输出 PWM，还必须修改 PWM timer 配置。
- 固定 `BOARD_ADC_BRICK1_VALID = 1` 是当前最小系统板阶段的简化，不等于以后真实飞行电源监测已经完成。

## 调试方法

后续上板时可以按下面顺序确认没有回归：

1. 完全断电冷启动。
2. 检查 QSPI / 参数：
   - `mtd status`
   - `param save`
   - 重启后 `param show`
3. 检查 TF 卡：
   - `mount`
   - `dmesg`
   - `/fs/microsd` 是否挂载。
4. 检查 QGC / NSH：
   - QGC 是否连接。
   - NSH 是否可执行 `dmesg`。
5. 后续做 PWM 前，再确认 `PA15` 已不会被任何 power-valid 逻辑重新占用。

## 复盘要点

这次整理的重点不是“让电源管理完整”，而是先把当前 H743mini 没有的 V6C 电源电路从真实外设引脚上让出来。

这种处理方式比直接删除更适合当前阶段：

- 保留了 V6C 来源说明。
- 避免误驱动 QSPI、TF 卡和未来 PWM 引脚。
- 编译验证通过。
- 后续仍可根据真实硬件逐步恢复或重建电源管理。
