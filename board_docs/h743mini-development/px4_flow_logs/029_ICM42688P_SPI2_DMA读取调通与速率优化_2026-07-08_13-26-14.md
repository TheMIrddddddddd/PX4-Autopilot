# 029 ICM42688P SPI2 DMA 读取调通与速率优化

时间：2026-07-08 13:26:14

## 任务目标

本轮目标是把外接 `ICM42688P` 主 IMU 从“能被 PX4 probe 到”推进到“可以稳定通过 SPI2 + DMA 读取 FIFO 数据，并能被 PX4 sensors/vehicle_imu 链路使用”。

这次不是单纯打开一个驱动，而是完整经历了：

- 确认 ICM42688P 引脚和 SPI2 设备表。
- 启用 SPI2 与 SPI2 DMA。
- 从 CPU 轮询读取切换到 DMA 读取。
- 通过 `icm42688p status`、`top`、`listener vehicle_imu_status` 分层判断问题。
- 发现并定位 DMA 后的 `bad transfer` 本质是 FIFO 包头错误。
- 调整 SPI 传输速度、ICM 内部 ODR、PX4 FIFO 读取频率，最终得到稳定参数。

本轮最终目标不是追求官方 V6C 的最高 24 MHz / 8 kHz 配置，而是在当前 H743mini 最小系统板 + 外接 ICM42688P 模块 + 杜邦线临时接线条件下，找到稳定、低 CPU、可解释的工作点。

```c
#define DMAMAP_SPI2_RX    DMAMAP_DMA12_SPI2RX_0
#define DMAMAP_SPI2_TX    DMAMAP_DMA12_SPI2TX_0
```

## 本轮修改内容

### 1. SPI2 设备表从 V6C 遗留结构改成 H743mini 实际 ICM

原始 V6C 逻辑中，ICM42688P 位于 SPI1：

```text
SPI1 + PC13 CS + PE6 DRDY
```

但当前 H743mini 外接 ICM42688P 实际规划为：

```text
SPI2 PC2/PC3/PD3 + PE4 CS + PE6 DRDY
```

因此在 `boards/gjl/h743mini/src/spi.cpp` 中将 ICM42688P 设备表改为：

```cpp
initSPIBus(SPI::Bus::SPI2, {
	initSPIDevice(DRV_IMU_DEVTYPE_ICM42688P, SPI::CS{GPIO::PortE, GPIO::Pin4},
		       SPI::DRDY{GPIO::PortE, GPIO::Pin6})
}),
```

同时不再继续使用 V6C 遗留的 BMI055 和 SPI1 ICM 设备表，也不再给 `initSPIBus()` 传旧的 `PB2` sensor power enable。`PB2` 当前已保留给 GD25Q128 的 QSPI CLK。

### 2. 启用 SPI2 与 SPI2 DMA

在 `boards/gjl/h743mini/nuttx-config/nsh/defconfig` 中启用：

```text
CONFIG_STM32H7_SPI2=y
CONFIG_STM32H7_SPI2_DMA=y
CONFIG_STM32H7_SPI2_DMA_BUFFER=1024
CONFIG_STM32H7_SPI_DMA=y
CONFIG_STM32H7_SPI_DMATHRESHOLD=8
```

关键含义：

- `CONFIG_STM32H7_SPI2=y`：打开 STM32H7 的 SPI2 外设。
- `CONFIG_STM32H7_SPI_DMA=y`：允许 SPI 驱动走 DMA 路径。
- `CONFIG_STM32H7_SPI2_DMA=y`：给 SPI2 具体启用 DMA。
- `CONFIG_STM32H7_SPI2_DMA_BUFFER=1024`：给 SPI2 驱动内部准备 DMA-safe bounce buffer。
- `CONFIG_STM32H7_SPI_DMATHRESHOLD=8`：小于等于 8 字节的小 SPI 传输用普通 CPU 方式，大的 FIFO burst 读走 DMA。

`DMA_BUFFER=1024` 很关键。它让 NuttX SPI2 驱动自己维护一块对齐的 DMA 缓冲区，避免上层传入的栈缓冲或普通内存因为 cache / 对齐问题导致 DMA 行为不稳定。

### 3. 增加 ICM42688P FIFO 错误细分计数

最开始 `icm42688p status` 只看到：

```text
icm42688p: bad transfer: xxxx events
```

这个信息太粗，无法判断是：

- SPI `transfer()` 本身失败。
- FIFO count 读失败。
- FIFO data 读失败。
- FIFO 包头不对。
- 温度字段异常。

因此在 `ICM42688P.cpp/hpp` 中增加了四个细分 perf counter：

```text
FIFO count transfer
FIFO data transfer
FIFO bad header
FIFO bad temperature
```

最终证明：

```text
FIFO count transfer: 0
FIFO data transfer: 0
FIFO bad header: 持续增长
```

这说明 DMA 事务本身并没有返回失败，真正的问题是 FIFO 长包读回来的数据包头不符合 ICM42688P 驱动预期。

### 4. ICM42688P ODR 从 8 kHz 降到 4 kHz

原驱动使用：

```text
gyro ODR = 8 kHz
accel ODR = 8 kHz
FIFO_SAMPLE_DT = 1e6 / 8000
```

调试过程中发现：

- `2 MHz SPI` 下 FIFO 包头稳定，但 `8 kHz ODR` 会导致 FIFO overflow。
- `8/12/16/24 MHz SPI` 能提高传输速度，但 FIFO bad header 会持续增长。
- `2500/3000 kHz SPI` 仍然“两头不讨好”：既不够稳定，也不能彻底解决问题。

因此最终把 ICM 内部 ODR 降到 `4 kHz`：

```cpp
static constexpr float FIFO_SAMPLE_DT{1e6f / 4000.f};
```

并新增寄存器位：

```cpp
GYRO_ODR_4KHZ_SET
GYRO_ODR_4KHZ_CLEAR
ACCEL_ODR_4KHZ_SET
ACCEL_ODR_4KHZ_CLEAR
```

然后将配置项改为：

```cpp
GYRO_ODR_4KHZ_SET / GYRO_ODR_4KHZ_CLEAR
ACCEL_ODR_4KHZ_SET / ACCEL_ODR_4KHZ_CLEAR
```

### 5. 启动脚本固定到 2 MHz SPI

在 `boards/gjl/h743mini/init/rc.board_sensors` 中启用：

```sh
icm42688p -R 0 -s -f 2000 start
```

含义：

- `-R 0`：当前先按无旋转处理，后续再按 IMU 实际安装方向确认。
- `-s`：启动内部 SPI 总线设备。
- `-f 2000`：PX4 I2C/SPI driver CLI 会把该值乘以 1000，因此实际 SPI 频率为 `2 MHz`。
- `start`：启动驱动。

### 6. 运行时参数设为 800 Hz

通过 NSH 执行：

```sh
param set IMU_GYRO_RATEMAX 800
param save
icm42688p stop
icm42688p -R 0 -s -f 2000 start
```

`IMU_GYRO_RATEMAX` 是 PX4 IMU gyro 处理链路的最大目标频率。ICM42688P 驱动启动时会读取该参数，并通过 `ConfigureSampleRate(_px4_gyro.get_max_rate_hz())` 计算 FIFO watermark 和读取间隔。

最终 `icm42688p status` 显示：

```text
FIFO empty interval: 1250 us (800.0 Hz)
```

说明从之前 `2500 us / 400 Hz` 成功提升到了 `1250 us / 800 Hz`。

## 概念解释

### 1. ODR 是什么

`ODR` 是 `Output Data Rate`，也就是芯片内部“产出原始数据”的速度。

本轮最终配置是：

```text
ICM42688P gyro/accel ODR = 4 kHz
```

这表示 ICM42688P 每秒大约产生 4000 组 gyro/accel 原始采样。

可以把它理解成：

```text
ODR = 芯片往 FIFO 里塞数据的速度
```

### 2. FIFO 是什么

`FIFO` 可以理解为芯片内部的“小仓库”。

ICM42688P 不是每产生一组数据就必须让 STM32 立刻读走，而是先把数据放进 FIFO。PX4 驱动每隔一段时间来读一次，一次可以读走多组样本。

如果芯片产数据太快，STM32 读得太慢，就会出现：

```text
FIFO overflow
```

意思是 FIFO 仓库装满了，新数据来不及放进去或旧数据被迫丢弃。

### 3. SPI 频率是什么

SPI 频率是 STM32H743 和 ICM42688P 之间“搬数据”的总线时钟。

本轮最终启动命令：

```sh
icm42688p -R 0 -s -f 2000 start
```

在 PX4 里，`-f 2000` 会换算成：

```text
2000 * 1000 = 2,000,000 Hz = 2 MHz
```

可以理解成：

```text
SPI 频率 = STM32 从 FIFO 仓库搬走数据的速度
```

注意：`2 MHz` 不是每秒 2 MB。SPI 频率是 bit 级时钟，理论字节吞吐要先除以 8，还要考虑命令字节、片选开销、驱动调度开销等。

### 4. 400 Hz / 800 Hz 是什么

`400 Hz` 或 `800 Hz` 是 PX4 驱动“多久读一次 FIFO / 发布一次 FIFO 包”的频率，不等于芯片内部 ODR。

最终配置是：

```text
ODR = 4 kHz
FIFO 读取/发布 = 800 Hz
SPI = 2 MHz
```

含义是：

```text
ICM42688P 每秒产生约 4000 组原始样本
PX4 每秒读约 800 次 FIFO
每次读约 4000 / 800 = 5 组样本
STM32 用 2 MHz SPI 把这 5 组样本搬出来
```

### 5. DMA 是什么

`DMA` 是 `Direct Memory Access`，可以理解成一个“专门搬数据的小助手”。

没有 DMA 时，CPU 自己盯着 SPI，一个字节一个字节等数据、搬数据。这样在高频 IMU FIFO 读取时，`wq:SPI2` CPU 占用很高。

有 DMA 后，CPU 只负责告诉 DMA：

```text
从 SPI2 收这么多字节，放到这个内存缓冲区
```

然后 DMA 控制器自己搬，搬完再通知 CPU。这样 CPU 不用一直忙等。

本轮现象：

- 未启用 DMA 时，IMU 数据能读，但 `wq:SPI2` CPU 占用很高，曾接近 `59%~61%`。
- 启用 DMA 并调通后，用户观察 `wq:SPI2` 约 `2.9%`。

### 6. bad transfer 和 FIFO bad header 的区别

`bad transfer` 是 ICM42688P 驱动里的总错误计数，名字容易误导。

它不一定表示 SPI 外设硬件传输失败，也可能是“传输完成了，但读回来的内容不符合预期”。

本轮通过新增细分计数发现：

```text
FIFO count transfer: 0
FIFO data transfer: 0
FIFO bad header: 持续增长
```

说明：

- SPI/DMA `transfer()` 没有返回失败。
- FIFO count 读也没失败。
- FIFO data 读也没返回失败。
- 但读回来的 FIFO 第一个字节，也就是 `FIFO_Header`，不符合 ICM42688P 的数据包格式。

因此真正的问题是：

```text
FIFO 长 burst 读回来的数据内容不可靠
```

而不是简单的：

```text
SPI 完全不通
```

### 7. DRDY 是什么

`DRDY` 是 `Data Ready`，数据就绪中断。

ICM42688P 的 `PE6 DRDY` 会告诉 STM32：

```text
FIFO 里已经有足够数据，可以来读了
```

如果 PX4 没及时响应，或者数据读取/处理跟不上，就可能出现：

```text
DRDY missed
```

最终稳定配置中：

```text
DRDY missed: 0 events
```

说明数据就绪中断和 SPI2 读取节奏已经匹配。

## 调试流程

### 第一阶段：先让 ICM42688P 出现在 SPI2 上

最初目标不是立刻融合 EKF2，而是先让驱动 probe 成功。

启用 SPI2 和设备表后，NSH 中可以启动：

```sh
icm42688p -R 0 -s start
```

关键输出：

```text
icm42688p #0 on SPI bus 2
```

含义：

- PX4 找到了 `DRV_IMU_DEVTYPE_ICM42688P`。
- 设备在 SPI2 上。
- WHOAMI 等基础寄存器读通。

这一阶段说明“硬件基本通”和“PX4 板级设备表基本对”。

### 第二阶段：CPU 轮询读取能工作，但占用太高

不开 DMA 时，ICM42688P 能发布：

```sh
listener sensor_accel
listener sensor_gyro
listener vehicle_imu
```

能看到 `sensor_accel`、`sensor_gyro`、`vehicle_imu` 数据，说明 IMU 原始数据已经进入 PX4 uORB。

但 `top` 中 `wq:SPI2` CPU 占用很高，说明 CPU 被 SPI2 FIFO 读取拖住。

这就是 DMA 的需求来源：

```text
不是因为 CPU 方式不正确，而是因为 CPU 方式太贵
```

### 第三阶段：打开 DMA 后 CPU 降低，但 bad transfer 出现

启用 SPI2 DMA 后，`top` 中 `wq:SPI2` CPU 占用明显下降。

但 `icm42688p status` 中出现：

```text
bad transfer: 持续增加
```

最开始容易误判为：

```text
DMA 本身坏了
SPI2 DMA 配错了
```

但这个判断还不够精确，因为 `bad transfer` 是总错误计数。

### 第四阶段：增加细分计数，定位到 FIFO bad header

增加细分 perf counter 后，结果变成：

```text
FIFO count transfer: 0
FIFO data transfer: 0
FIFO bad header: 持续增长
FIFO bad temperature: 0
```

这一步非常关键。

它把问题从“DMA 不行”缩小到：

```text
DMA 传输函数没有报错，但 FIFO 长包数据内容不符合格式
```

也就是 FIFO 数据包头被读坏、读偏，或者高速长 burst 下信号质量不稳定。

### 第五阶段：对照 V6C，但不盲目照抄

读取 V6C 源码后确认：

```text
V6C 的 ICM42688P 在 SPI1
V6C 的 SPI2 用于 FRAM/Flash
```

V6C 的 ICM 启动：

```sh
icm42688p -R 6 -s start
```

驱动默认 SPI 频率：

```text
24 MHz
```

但当前 H743mini 的实际硬件是：

```text
ICM42688P 外接在 SPI2 PC2/PC3/PD3 + PE4 + PE6
```

因此不能直接说：

```text
V6C 24 MHz 能跑，我这里也一定能跑
```

因为 V6C 是板载 PCB 走线和 SPI1 传感器总线，当前是最小系统板外接模块，真实线长、接地、模块板、连接方式都不同。

当前实物测试使用的是杜邦线临时连接。这个条件必须单独记录，因为 SPI 不是普通低速开关量信号，尤其是 `SCK` 时钟线在几 MHz 到几十 MHz 时会受到线长、地线回流路径、接触电阻、串扰和反射影响。

因此本轮结论只能说：

```text
在当前杜邦线接法下，2 MHz SPI + 4 kHz ODR + 800 Hz FIFO 读取已经稳定
```

不能直接推出：

```text
当前杜邦线接法也能稳定跑 V6C 的 24 MHz SPI
```

后续 PCB 画完并使用短走线、完整地参考和更稳定的供电去耦后，需要重新测试 SPI 频率余量。也就是说，高速失败不一定是 ICM42688P 芯片能力不够，更可能是当前临时接线条件限制了 SPI 信号质量。

#### 杜邦线为什么会影响 SPI

SPI 到几 MHz 以后，就不能只当普通低速 GPIO 看。

这里容易误解的一点是：

```text
2 MHz / 8 MHz / 24 MHz 不是唯一问题
真正影响波形的是数字信号的边沿速度
```

STM32H743 的 GPIO 翻转边沿很快。哪怕 SPI 设置成 `2 MHz`，SCK 也是方波，方波边沿里包含比 2 MHz 高得多的高频成分。杜邦线变长以后，会带来：

- 反射：信号到线尾后反弹回来，导致过冲、下冲或二次边沿。
- 回流路径差：电流不是只从信号线过去，还要从地线回来；如果旁边没有地，回流绕远路，波形会变差。
- 串扰：SCK 边沿很快，容易把毛刺耦合到旁边的 MISO/MOSI/CS。
- 接触不稳定：杜邦线和排针接触电阻、插拔状态不如焊接或 PCB 走线稳定。
- 面包板更差：面包板内部金属片会额外引入寄生电容和寄生电感，不适合高速 SPI。

本轮现象与这个判断一致：

```text
高 SPI 频率：FIFO bad header 增长
2 MHz SPI：FIFO bad header 不涨
```

这说明高频下不是“完全不能通信”，而是长 FIFO burst 中个别 bit 被读错，最终体现为 FIFO 包头不合法。

#### PCB 上每根线应该怎么画

当前 ICM42688P 是一个外接模块，不是直接贴裸芯片。PCB 设计时可以把它理解成：

```text
STM32H743 <-> 载板走线 <-> ICM42688P 模块排针/焊盘 <-> 模块内部芯片
```

所以载板上仍然需要按高速数字线处理 SPI。原则是：短、直、靠近地、少过孔、少分叉、远离噪声源。

| 信号 | 重要程度 | 推荐画法 | 为什么 |
|---|---|---|---|
| `SCK` | 最高 | 最短、最直、旁边有连续 GND，尽量不换层；STM32 端预留 `22~68Ω` 串联电阻 | SCK 是采样时钟，边沿质量直接决定 ICM 和 STM32 在什么时候采样数据 |
| `MISO` | 很高 | 最短、靠近 GND；ICM 模块端或模块连接器附近预留 `22~68Ω` 串联电阻 | MISO 是 ICM 回传 FIFO 数据，`FIFO bad header` 很可能就是 MISO 采样瞬间不稳定 |
| `MOSI` | 高 | 最短、靠近 GND；STM32 端预留 `22~68Ω` 串联电阻 | MOSI 是 STM32 发命令给 ICM，命令错会导致寄存器/FIFO 读取异常 |
| `CS` | 高 | 远离 SCK 噪声，靠近 GND；STM32 端预留 `22~68Ω` 串联电阻，可预留 `10k` 上拉到 3.3V | CS 决定一次 SPI 事务的开始和结束，毛刺可能让 ICM 误判帧边界 |
| `DRDY` / `INT` | 中 | 可以比 SPI 稍宽松，但不要贴着 SCK 长距离并行；必要时预留小电阻或 `10k` 上拉/下拉位 | DRDY 是数据就绪中断，频率低，但误触发会导致读取节奏异常 |
| `3.3V` | 很高 | 走线要短且够宽，模块连接器附近放 `0.1uF + 1uF`，可再预留 `4.7uF` | IMU 对供电噪声敏感，SPI burst 和数字翻转会让电源瞬间扰动 |
| `GND` | 最高 | 模块附近多打地过孔，底层或内层尽量保持完整地平面，信号线下方不要切地 | 所有高速信号都需要返回电流路径，地不好时信号线也会变差 |

串联电阻的意义不是“限流”，而是让边沿不要那么冲，减少反射和振铃。优先预留焊盘，初版可以先焊 `0Ω`，如果示波器看到 SCK/MISO 有明显过冲、下冲或振铃，再换成 `22Ω`、`33Ω`、`47Ω`、`68Ω` 试。

#### 具体到当前 ICM42688P 这几根线

当前最终引脚是：

```text
SPI2_SCK  = PD3 / P2-38
SPI2_MISO = PC2
SPI2_MOSI = PC3
CS        = PE4
DRDY      = PE6
VCC       = 3.3V
GND       = GND
```

PCB 上建议这样处理：

1. `PD3/SCK`
   - 最优先控制。
   - 线尽量短，不要绕远。
   - 不要和 MISO/MOSI/DRDY 长距离紧贴平行。
   - 下方必须有完整 GND。
   - 在 STM32 端附近预留串联电阻位，默认可先 `0Ω`，不稳定再换 `22~68Ω`。

2. `PC2/MISO`
   - 这是 ICM 到 STM32 的数据回传线。
   - 读 FIFO 长包时，最终数据正确性主要看 MISO 在采样点是否稳定。
   - 如果要加串联电阻，原则上靠近信号源，也就是靠近 ICM 模块端或模块连接器端。
   - 不要让 MISO 长距离贴着 SCK 走，否则 SCK 的尖边沿可能耦合到 MISO。

3. `PC3/MOSI`
   - 这是 STM32 到 ICM 的命令线。
   - 串联电阻靠近 STM32 端预留。
   - 与 SCK 可以同方向短距离走，但不要长距离无地隔离并行。

4. `PE4/CS`
   - CS 必须干净，不能有毛刺。
   - 建议预留 `10k` 上拉到 3.3V，让上电和复位阶段默认不选中 ICM。
   - 如果 CS 线较长，也可在 STM32 端预留 `22~68Ω` 串联电阻。

5. `PE6/DRDY`
   - DRDY 不是 SPI 高速数据线，但它决定 PX4 什么时候去读 FIFO。
   - 不要和 SCK 长距离并行。
   - 如果模块 DRDY 是推挽输出，一般不需要强上拉；如果不确定，可以预留 `10k` 上拉/下拉位，实际焊不焊看模块输出方式和波形。

6. `3.3V/GND`
   - ICM 模块必须和 STM32 共地。
   - 模块供电入口附近建议放：
     - `0.1uF` 陶瓷电容，靠近模块 VCC/GND。
     - `1uF` 陶瓷电容，靠近模块 VCC/GND。
     - 可选 `4.7uF`，作为模块局部储能。
   - 电容越靠近模块供电脚越有效，远处电容不能完全替代近端去耦。

#### 模块上已经有电容，还需要再加吗

如果买的是 ICM42688P 模块，模块板上通常可能已经有：

- LDO 稳压器。
- 电源指示 LED。
- 一个或多个小电容。
- 上拉电阻或电平相关电阻。

但现在不知道你这个最小模块具体放了什么，所以不能假设它已经足够。

判断方法：

1. 看模块正反面有没有靠近 `VCC/GND` 的小贴片电容。
2. 看有没有 LDO，通常是 3 脚或 5 脚小芯片。
3. 看模块丝印是否支持 `3.3V` 或 `5V` 输入。
4. 用万用表确认模块 `VCC` 和芯片供电脚之间是不是直连，还是经过 LDO。

工程上建议即使模块板已有电容，载板上也预留电容：

```text
模块 VCC/GND 入口附近：0.1uF + 1uF
空间允许：再预留 4.7uF
```

原因是模块内部电容只能照顾模块内部，载板连接器、排针、走线、电源分配也会引入阻抗。载板入口再放一组去耦，可以降低供电线和连接器带来的瞬态压降。

如果模块只引出了 `VCC/GND/SCK/MISO/MOSI/CS/INT`，没有单独 `VDDIO`，那就按模块定义供电。当前模块没有 `VDDIO` 引脚，并不代表芯片内部没有 I/O 电源域，而是模块板已经把它处理掉了。对你来说，重点是：

```text
模块 VCC 用 3.3V
模块 GND 和飞控 GND 共地
SPI 信号也是 3.3V 逻辑
```

不要给 SPI 信号接 5V。

#### PCB 复测时怎么判断画线是否成功

PCB 完成后，不要一上来就直接跑 `24 MHz`。建议按本轮稳定点反向验证：

1. 先用当前稳定配置启动：

```sh
icm42688p -R 0 -s -f 2000 start
```

确认：

```text
FIFO bad header = 0
FIFO overflow = 0
DRDY missed = 0
```

2. 再逐步提高 SPI 频率：

```sh
icm42688p stop
icm42688p -R 0 -s -f 4000 start

icm42688p stop
icm42688p -R 0 -s -f 8000 start

icm42688p stop
icm42688p -R 0 -s -f 12000 start

icm42688p stop
icm42688p -R 0 -s -f 16000 start

icm42688p stop
icm42688p -R 0 -s -f 24000 start
```

每一档都看：

```sh
icm42688p status
listener vehicle_imu_status
top
```

如果某一档开始出现 `FIFO bad header`，优先怀疑 SPI 波形、SCK/MISO 采样裕量、串联电阻和地回流，而不是立刻改 PX4 驱动。

### 第六阶段：扫 SPI 频率，分清“传得快”和“传得稳”

测试过不同 SPI 频率：

- `24 MHz`
- `16 MHz`
- `12 MHz`
- `8 MHz`
- `3 MHz`
- `2.5 MHz`
- `2 MHz`

现象总结：

```text
高频：速度够，但 FIFO bad header 增长
2 MHz：FIFO bad header 不涨，但 8 kHz ODR 下 FIFO overflow
```

这说明问题不是单纯“速度越快越好”。

需要同时满足：

```text
SPI 读回来的数据要正确
FIFO 不能因为读得太慢而溢出
CPU 占用不能太高
```

### 第七阶段：ODR 从 8 kHz 降到 4 kHz

`2 MHz SPI` 是稳定的，但在 `8 kHz ODR` 下 FIFO 进数据太快，会 overflow。

因此不是继续硬拉 SPI 频率，而是把 ICM 内部产数速度减半：

```text
8 kHz ODR -> 4 kHz ODR
```

这样每秒进入 FIFO 的原始样本数减半，SPI2 在 2 MHz 下就有更多余量。

结果：

```text
FIFO overflow: 0
accel_raw_rate_hz / gyro_raw_rate_hz ≈ 3957.8879 Hz
```

说明 4 kHz ODR 生效，FIFO 不再溢出。

### 第八阶段：把 FIFO 读取从 400 Hz 提到 800 Hz

4 kHz ODR + 2 MHz SPI 下，最开始 FIFO 读取是 400 Hz：

```text
FIFO empty interval: 2500 us (400.0 Hz)
```

此时每次大约读：

```text
4000 / 400 = 10 组样本
```

后来通过参数：

```sh
param set IMU_GYRO_RATEMAX 800
param save
```

并重启 ICM 驱动后，FIFO 读取提升到 800 Hz：

```text
FIFO empty interval: 1250 us (800.0 Hz)
```

此时每次大约读：

```text
4000 / 800 = 5 组样本
```

每次 burst 更短，单次 SPI 传输压力更小，最终错误计数保持 0。

## 关键命令解释

### 1. 停止 ICM42688P 驱动

```sh
icm42688p stop
```

作用：

- 停止当前正在运行的 ICM42688P 驱动实例。
- 修改参数或重新指定 SPI 频率后，需要先停再启，让驱动重新读取配置。

什么时候用：

- 修改 `IMU_GYRO_RATEMAX` 后。
- 想换 `-f` SPI 频率测试时。
- 需要清零驱动内部 perf counter，从头观察错误是否增长时。

### 2. 启动 ICM42688P 驱动

```sh
icm42688p -R 0 -s -f 2000 start
```

含义：

- `icm42688p`：启动 InvenSense ICM42688P IMU 驱动。
- `-R 0`：传感器旋转方向先设为 `0`，表示暂不旋转。
- `-s`：使用内部 SPI 总线。
- `-f 2000`：SPI 频率参数，PX4 内部会乘以 1000，因此实际为 `2 MHz`。
- `start`：启动驱动。

为什么最终用 `-f 2000`：

- 2 MHz 下 FIFO 包头稳定。
- 更高频率在当前接线和模块条件下容易出现 `FIFO bad header`。
- 降 ODR 到 4 kHz 后，2 MHz 已经足够搬运 FIFO 数据。

### 3. 查看 ICM42688P 驱动状态

```sh
icm42688p status
```

作用：

- 查看驱动跑在哪条总线。
- 查看 FIFO 读取间隔。
- 查看错误计数。

关键字段：

```text
FIFO empty interval: 1250 us (800.0 Hz)
bad register
bad transfer
FIFO count transfer
FIFO data transfer
FIFO bad header
FIFO overflow
DRDY missed
```

最终稳定状态应该是：

```text
bad register: 0
bad transfer: 0
FIFO bad header: 0
FIFO overflow: 0
DRDY missed: 0
```

`FIFO reset: 1` 通常是启动时初始化 FIFO 的一次 reset，不是持续错误。

### 4. 修改 IMU FIFO 读取/发布目标频率

```sh
param set IMU_GYRO_RATEMAX 800
```

作用：

- 把 PX4 IMU gyro 处理链路的最大目标频率设为 800 Hz。
- ICM42688P 驱动启动时会读取这个参数，用它计算 FIFO watermark 和读取间隔。

当前结果：

```text
FIFO empty interval: 1250 us (800.0 Hz)
```

注意：

- 改参数后，需要重启 ICM 驱动或重启飞控，驱动才会重新读取该值。
- 这个参数影响的是 PX4 读 FIFO / 发布 FIFO 包的频率，不是 ICM 芯片内部 ODR。

### 5. 保存参数

```sh
param save
```

作用：

- 把当前参数保存到持久化存储。
- 当前项目参数存储已迁移到 GD25Q128 的 `/fs/mtd_params`。

本轮 `IMU_GYRO_RATEMAX=800` 已通过 `param save` 保存。

### 6. 查看 vehicle_imu_status

```sh
listener vehicle_imu_status
```

作用：

- 查看 PX4 sensors 模块统计出的 IMU 状态。
- 可以确认 raw rate、发布 rate、错误计数、振动指标、均值和方差。

最终关键输出：

```text

gyro_error_count: 0
accel_rate_hz: 791.5776
gyro_rate_hz: 791.5776
accel_raw_rate_hz: 3957.8879
gyro_raw_rate_hz: 3957.8879
```

解释：

- `raw_rate_hz ≈ 3957.9`：ICM 内部 ODR 接近 4 kHz。
- `rate_hz ≈ 791.6`：PX4 读取/发布频率接近 800 Hz。
- `error_count = 0`：最终链路没有持续错误。

### 7. 查看 CPU 占用

```sh

```

作用：

- 查看各任务 CPU 占用。

本轮用户观察：

说明：

- SPI2 读取已经不是高 CPU 占用任务。

查看 PX4 sensors 模块选中的 gyro/accel，以及传感器 validator 状态。

## 复盘要点

这次调试最有价值的地方，不是“最后改成了几个参数”，而是把问题分层拆开。

可以总结成五个判断：

1. 能 probe 到 ICM42688P，只说明短寄存器读写通了，不代表 FIFO 长包读取稳定。
2. `bad transfer` 是总错误，必须继续拆成 `FIFO data transfer`、`FIFO bad header` 等细项。
3. DMA 降 CPU 是对的，但 DMA 后读到坏数据，不一定是 DMA 控制器失败，也可能是高速长 burst 下数据内容不可靠。
4. 官方 V6C 的 24 MHz ICM 配置不能直接照搬，因为 V6C 的 ICM 在 SPI1 板载传感器总线上，当前 H743mini 是外接 ICM 走 SPI2。
5. 当前是杜邦线临时接法，2 MHz 是当前实物链路验证过的稳定点；等 PCB 完成后，需要重新评估 SPI 高频余量。
6. 最终稳定点来自三者平衡：
   - ODR 不能让 FIFO 进数据太快。
   - SPI 频率要在当前物理链路上稳定。
   - DMA 要让 CPU 不再忙等。

本轮最终平衡点：

```text
ICM ODR = 4 kHz
PX4 FIFO 读取/发布 = 800 Hz
SPI2 频率 = 2 MHz
SPI2 DMA = enabled
```

## 面试讲述版本

可以这样讲：

> 我在给 STM32H743 最小系统板接入外部 ICM42688P 主 IMU 时，先从硬件连接和 PX4 板级设备表开始。官方 V6C 的 ICM42688P 是挂在 SPI1 上，而我的最小系统板规划是把 ICM 接到 SPI2，具体是 `PC2/PC3/PD3 + PE4 CS + PE6 DRDY`。所以第一步不是直接照抄 V6C，而是重写 H743mini 的 SPI 设备表，让 PX4 能在 SPI2 上 probe 到 ICM42688P。
>
> 初始 probe 成功以后，我可以通过 `listener sensor_accel`、`listener sensor_gyro`、`listener vehicle_imu` 看到 IMU 数据，这说明基础通信链路是通的。但用 `top` 看 CPU 时，发现 `wq:SPI2` 占用很高，说明 CPU 正在花很多时间轮询 SPI FIFO 数据。为了降低 CPU 占用，我启用了 SPI2 DMA。
>
> 启用 DMA 后，CPU 占用确实下降了，但 `icm42688p status` 开始出现大量 `bad transfer`。这个名字容易误导，好像是 DMA 或 SPI transfer 本身失败。为了进一步定位，我在驱动里增加了四个细分计数：`FIFO count transfer`、`FIFO data transfer`、`FIFO bad header`、`FIFO bad temperature`。结果发现 transfer 本身并没有失败，真正持续增长的是 `FIFO bad header`。这说明 DMA 事务完成了，但 FIFO 长包读回来的数据包头不合法。
>
> 接着我对比了 V6C 源码，确认 V6C 的 ICM 在 SPI1，SPI2 是给 FRAM 用的；而我当前硬件是外接模块挂 SPI2，并且现阶段是用杜邦线临时连接，不是 PCB 板载短走线。所以不能简单认为 V6C 能 24 MHz，我这里也能 24 MHz。我测试了多档 SPI 频率：高频时速度够，但 FIFO 包头会坏；2 MHz 时包头稳定，但在 8 kHz ODR 下 FIFO 又会 overflow。
>
> 这个现象说明问题不是单纯提高 SPI 速度，而是要平衡三个速度：ICM 内部产数据的 ODR、PX4 读 FIFO 的频率、SPI 总线搬数据的速度。最后我把 ICM ODR 从 8 kHz 降到 4 kHz，让芯片每秒产生的数据减半；同时把 SPI 固定在稳定的 2 MHz；再通过 `IMU_GYRO_RATEMAX=800` 让 PX4 每秒读大约 800 次 FIFO，每次读约 5 组样本。
>
> 最终 `icm42688p status` 显示 `FIFO empty interval: 1250 us (800 Hz)`，`bad register`、`bad transfer`、`FIFO bad header`、`FIFO overflow`、`DRDY missed` 全部为 0；`vehicle_imu_status` 显示 raw rate 约 3958 Hz、发布 rate 约 792 Hz；`top` 中 `wq:SPI2` 约 2.9%。这说明 IMU 已经从 CPU 高占用读取，调通到了 SPI2 DMA 低占用稳定读取。
>
> 这次调试的核心经验是：嵌入式问题不能只看一个错误名，也不能直接套官方板子的频率。要先把链路拆成硬件连接、短寄存器读写、长 FIFO burst、DMA buffer、数据格式、调度频率和 CPU 占用，再逐层用命令验证。当前 2 MHz 是杜邦线临时连接下的稳定工程点，等 PCB 画完以后，还要重新测试更高 SPI 频率是否能稳定。
