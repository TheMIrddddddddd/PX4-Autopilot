## 概念

飞控外设引脚规划需要同时看三件事：

```text
芯片复用能力
  -> 这个 GPIO 能不能复用成 UART / I2C / SPI / TIM PWM / ADC

最小系统板实际引出情况
  -> 这个 GPIO 是否在排针上方便接线，还是只在 FPC/屏幕/摄像头接口上

PX4 当前源码默认占用
  -> 这个 GPIO 是否已经被 board.h、board_config.h、timer_config.cpp 等文件占用
```

本轮重点区分了几个容易混淆的概念：

- `POWER` 供电和电压/电流检测不是一回事。
- `PC4` / `PC5` 是电流/电压 ADC 检测规划。
- `PA15` 在原 FMU-v6C 源码中是电源 Brick 有效状态输入，不是 ADC。
- `PB3` 可作为 `TRACESWO/JTDO` 调试输出，但当前 4pin SWD 下载只使用 `PA13/SWDIO` 和 `PA14/SWCLK`。
- 电机 PWM 可以跨多个定时器，但四路统一到同一个定时器更规整。

## 排查过程

本轮从“官方 FMU-v6C 电机输出怎么安排”开始，对照了当前最小系统板实际能用的排针。

最初官方 FMU-v6C 风格的直接 PWM 映射是：

```text
FMU_CH1 -> PA8  / TIM1_CH1
FMU_CH2 -> PE11 / TIM1_CH2
FMU_CH3 -> PE13 / TIM1_CH3
FMU_CH4 -> PE14 / TIM1_CH4
FMU_CH5 -> PD14 / TIM4_CH3
FMU_CH6 -> PD15 / TIM4_CH4
FMU_CH7 -> PA0  / TIM5_CH1
FMU_CH8 -> PA1  / TIM5_CH2
```

但当前板子存在几个限制：

- `PE11` / `PE13` / `PE14` 已被 SDRAM 使用，不能用于电机 PWM。
- `PA0` / `PA1` 虽然可复用为定时器输出，但板上连接了 `WAKE_UP` / 自定义按键电路，不优先用于电机。
- `PB14` / `PB15` 可用作 `TIM12_CH1/CH2`，但只能提供两路。
- `PB10` / `PB11` 可用作 `TIM2_CH3/CH4`，但当前源码中是 I2C2。
- `PH10` / `PH11` / `PH12` / `PI0` 看起来能组成 `TIM5` 四路，但同时是 FMC/SDRAM 数据线，不能使用。

最终选择 `TIM2` 的四路：

```text
PA15 / PB3 / PB10 / PB11
```

这样可以让四个电机统一到 `TIM2_CH1~CH4`，并且都在当前 GPIO 排针上方便引出。

## 当前结论与修复方向

当前引脚规划结论：

```text
GPS1:
  PA3 / USART2_RX
  PA2 / USART2_TX
  PB8 / I2C1_SCL
  PB7 / I2C1_SDA

POWER 检测:
  PC4 / ADC1_INP4 / CURRENT
  PC5 / ADC1_INP8 / VOLTAGE

RCIN:
  PC7 / USART6_RX / CRSF RX
  PC6 / USART6_TX / CRSF TX

电机 PWM:
  PA15 / TIM2_CH1
  PB3  / TIM2_CH2
  PB10 / TIM2_CH3
  PB11 / TIM2_CH4
```

PA15 的当前结论：

- `PA15` 在原 FMU-v6C 源码中是 `GPIO_nPOWER_IN_A`。
- 它用于判断 `Brick1` 电源输入是否有效，是数字状态检测。
- 它不是电池电压检测，也不是电流检测。
- 当前最小系统板没有完整 FMU-v6C 电源选择电路，所以可以释放 `PA15` 做电机 PWM。
- 后续源码必须避免 `PA15` 同时被 `GPIO_nPOWER_IN_A` 和 `TIM2_CH1` 占用。

PB3 的当前结论：

- `PB3` 可以作为 `TRACESWO/JTDO`。
- 当前 4pin SWD 下载只使用 `PA13/SWDIO` 和 `PA14/SWCLK`。
- 只要不使用 SWO/SWV trace，`PB3` 可作为 `TIM2_CH2` 电机 PWM。

## 常见坑

- 不要把“给 PX4 供电”和“PX4 检测电池电压/电流”混成一件事。
- 不要把 `PA15` 的 `GPIO_nPOWER_IN_A` 理解成电压/电流检测，它只是电源有效状态输入。
- 不要把电池正极直接接到 `PC5`，必须通过电源模块或分压，保证 ADC 不超过 `3.3V`。
- 不要把电调的大电流供电接到 MCU GPIO，电机 PWM 只接信号线和地线。
- 不要继续沿用 FMU-v6C 的 `PE11/PE13/PE14` 做电机 PWM，这些脚在当前 IIT6 板上已经给 SDRAM 使用。
- 不要同时把 `PB10/PB11` 当 I2C2 和电机 PWM 使用，后续必须二选一或重新分配。
- 不要用 `PH10/PH11/PH12/PI0` 做电机 PWM，它们和 FMC/SDRAM 数据线冲突。
- 不要以为 ELRS 和 CRSF 是同一层协议；ELRS 是遥控器到接收机的无线链路，CRSF 是接收机到飞控的 UART 协议。

## 调试方法

后续进入电机 PWM 真实改源码和验证时，建议按下面顺序做：

1. 先修改 `timer_config.cpp`，只保留或新增实际可用的 `TIM2_CH1~CH4`。
2. 在 `defconfig` 中确认启用 `CONFIG_STM32H7_TIM2=y`。
3. 释放 `PA15` 的 `GPIO_nPOWER_IN_A` 定义，避免同一引脚被两个功能占用。
4. 释放或迁移 `PB10/PB11` 的 `I2C2` 配置。
5. 编译 `make gjl_h743mini_default`。
6. 烧录后先不接电机，只用示波器或逻辑分析仪看四路 PWM。
7. 再接电调信号线和地线，保持不装桨测试。
8. 最后再结合 QGC actuator test 或 PX4 输出命令检查电机顺序。

建议每次只改一个外设组：

```text
先让 PWM 输出可见
  -> 再验证 RCIN
  -> 再验证 GPS
  -> 再接电压/电流检测
  -> 最后接 IMU/气压计并启动 EKF2
```

## 复盘要点

本轮最重要的结论不是“找到了四个能出 PWM 的脚”，而是把这四个脚放回整个飞控外设冲突图里看了一遍。

真正可用的引脚必须同时满足：

- 芯片支持对应复用功能。
- 当前最小系统板实际引出，方便接线。
- 不和 SDRAM、TF 卡、SWD、GPS、RCIN、ADC 检测等关键链路冲突。
- PX4 源码中后续能清晰释放旧功能并重新配置。

`TIM2_CH1~CH4` 方案目前是比较平衡的选择，但它不是零成本方案。它的主要成本是后续要释放 `PA15` 的电源有效检测逻辑，以及释放 `PB10/PB11` 的 I2C2 配置。
