## 本轮修改内容

### 1. EEPROM 容量配置

在 `boards/gjl/h743mini/default.px4board` 中加入：

```text
CONFIG_BOARD_COMPILE_DEFINITIONS="-DCONFIG_AT24XX_SIZE=16"
```

用途：

- 告诉 PX4 自带的 `px4_24xxxx_mtd.c`，当前 EEPROM 是 `16 Kbit`。
- 对应 `BL24C16F = 2048 bytes = 128 pages * 16 bytes`。
- 不启用 NuttX 原生 `CONFIG_MTD_AT24XX`，继续使用 PX4 自己的 AT24 MTD 路径。

### 2. I2C2 引脚映射

在 `boards/gjl/h743mini/nuttx-config/include/board.h` 中把 I2C2 从原 V6C 默认的 `PB10/PB11` 改到当前硬件实际连接：

```c
GPIO_I2C2_SCL_3 /* PH4 */
GPIO_I2C2_SDA_3 /* PH5 */
```

结论：

- `PH4/PH5` 是 I2C2 的第三组 alternate pin mapping，不是 I2C3。
- 板上 `i2cdetect -b 2` 已验证 `0x50~0x57` 全部响应，符合 BL24C16F 的 banked I2C address 特征。

### 3. AT24C16 / BL24C16F 协议适配

在 `platforms/nuttx/src/px4/common/px4_24xxxx_mtd.c` 中补齐 1 字节 word address 和 banked device address 逻辑：

```c
static uint8_t at24c_i2c_address(uint8_t base, uint16_t offset)
{
#if AT24XX_ADDRSIZE == 1
	return base + ((offset >> 8) & 0x07);
#else
	return base;
#endif
}
```

并通过 `at24c_pack_address()` 区分：

- AT24C16/BL24C16F：1 字节 word address，bank 位进入 I2C 设备地址。
- 24LC64 等较大 EEPROM：固定 I2C 设备地址，加 2 字节内部地址。

本轮已覆盖：

- `at24c_bread()` 读路径。
- `at24c_bwrite()` 写路径。
- `px4_at24c_initialize()` 初始化探测路径。

### 4. MTD manifest 从 I2C4 切到 I2C2

在 `boards/gjl/h743mini/src/board_config.h` 中把：

```c
#define PX4_I2C_BUS_MTD      4,5
```

改为：

```c
#define PX4_I2C_BUS_MTD      2
```

在 `boards/gjl/h743mini/src/mtd.cpp` 中把 EEPROM 设备改为：

```c
static const px4_mft_device_t i2c2 = {
	.bus_type = px4_mft_device_t::I2C,
	.devid    = PX4_MK_I2C_DEVID(2, 0x50)
};
```

当前 EEPROM 分区为：

```c
static const px4_mtd_entry_t eeprom = {
	.device = &i2c2,
	.npart = 2,
	.partd = {
		{
			.type = MTD_CALDATA,
			.path = "/fs/mtd_caldata",
			.nblocks = 112 // 1792 = 112 * 16
		},
		{
			.type = MTD_ID,
			.path = "/fs/mtd_id",
			.nblocks = 16 // 256 = 16 * 16
		}
	},
};
```

说明：

- `MTD_CALDATA` 承接 PX4 标准校准数据路径 `/fs/mtd_caldata`。
- `MTD_ID` 保留 256 bytes 的 ID 小分区 `/fs/mtd_id`。
- 原 V6C 的 SPI2 FRAM 分区目前没有加入 `board_mtd_config`，只作为后续 GD25Q128 阶段的参考上下文保留。

## 修改流程

1. 先阅读 BL24C16F 数据手册，确认其不是“固定 `0x50` + 2 字节内部地址”的大 EEPROM，而是 `0x50~0x57` bank 地址加 1 字节 word address。
2. 在 PX4 自带 `px4_24xxxx_mtd.c` 中补齐 AT24C16 级别 EEPROM 的地址打包和 bank 选择逻辑。
3. 把 `board.h` 的 I2C2 pin mapping 从 `PB10/PB11` 改为当前硬件原理图对应的 `PH4/PH5`。
4. 用 `CONFIG_BOARD_COMPILE_DEFINITIONS` 传入 `CONFIG_AT24XX_SIZE=16`，避免 NuttX Kconfig 因未启用原生 `CONFIG_MTD_AT24XX` 而丢弃 `CONFIG_AT24XX_SIZE`。
5. 在 `mtd.cpp` 里先用最小 `/fs/mtd_id` 验证 EEPROM 链路，再扩展为官方风格的 `/fs/mtd_caldata + /fs/mtd_id` 双分区。
6. 处理构建缓存时间戳导致的旧对象文件问题，强制重编 `px4_24xxxx_mtd.c` 后重新刷板验证。

## 当前结论

- EEPROM 物理链路已通：I2C2 `PH4/PH5` 能扫到 `0x50~0x57`。
- EEPROM 协议路径已通：BL24C16F 的 banked address 加 1 字节 word address 已适配到 PX4 `px4_24xxxx_mtd.c`。
- EEPROM MTD 几何已正确：`16 bytes * 128 blocks = 2048 bytes`。
- EEPROM MTD 分区已按当前目标完成：
  - `/fs/mtd_caldata`：1792 bytes。
  - `/fs/mtd_id`：256 bytes。
- EEPROM 不适合承担参数和任务数据的大容量存储；后续 `MTD_PARAMETERS`、可能的任务数据或 dataman 存储应优先放到 GD25Q128。
