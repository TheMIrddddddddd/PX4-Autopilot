## 概念

### 1. `tone_alarm` 与 `tune_control`

PX4 蜂鸣器链路分成两层：

```text
tune_control 负责发布“播放哪一个提示音”
tone_alarm   负责把提示音变成定时器输出波形
```

也就是说：

- `tune_control play -t 1` 是上层命令，表示播放启动音。
- `tone_alarm` 是底层驱动，订阅 `tune_control`，再用定时器输出频率变化的方波。
- 对无源蜂鸣器或压电片来说，真正让它发声的是 `TIM12_CH1` 在 `PB14` 上输出的波形。

### 2. 为什么是 PB14 / TIM12_CH1

此前主 MD 已经规划：

```text
PB14 -> TIM12_CH1 -> 无源蜂鸣器 / 压电片
```

`PB14` 在 STM32H743 NuttX pinmap 中有：

```c
GPIO_TIM12_CH1OUT_1
```

因此它适合作为 `tone_alarm` 的定时器输出脚。`PB14` 后续继续避让 `SDMMC2` 和 LCD 背光等功能。

### 3. `RCC_APB1ENR_TIM12EN` 与 `RCC_APB1LENR_TIM12EN`

本轮遇到的编译问题不是蜂鸣器引脚配置错，而是 STM32H7 的 RCC 宏命名与 PX4 通用 STM32 `tone_alarm` 代码不完全一致。

可以这样理解：

```text
STM32_RCC_APB1ENR        = RCC APB1 时钟使能寄存器地址
RCC_APB1ENR_TIM12EN      = 这个寄存器里打开 TIM12 时钟的 bit
```

而 STM32H7 把 APB1 相关寄存器拆成了低半区和高半区：

```text
STM32_RCC_APB1LENR
STM32_RCC_APB1HENR
```

TIM12 在 APB1 low enable register 中，所以 NuttX H7 头文件中真实存在的位宏是：

```c
RCC_APB1LENR_TIM12EN
```

但 PX4 `tone_alarm` PWM 接口里旧式通用代码仍使用：

```c
RCC_APB1ENR_TIM12EN
```

所以需要补一个“旧名字到新名字”的兼容别名：

```c
#if !defined(RCC_APB1ENR_TIM12EN) && defined(RCC_APB1LENR_TIM12EN)
# define RCC_APB1ENR_TIM12EN RCC_APB1LENR_TIM12EN
#endif
```

这句的意思是：

```text
如果旧名字 RCC_APB1ENR_TIM12EN 不存在，
并且新名字 RCC_APB1LENR_TIM12EN 存在，
就把旧名字定义成新名字。
```

它不是运行时逻辑，也不是改硬件寄存器，只是 C/C++ 预处理阶段的名字翻译。

### 4. QGC 解锁声音的含义

QGC 中点击“解锁 / Arm”后蜂鸣器响，按 PX4 代码含义更接近“解锁警示音”，不是故障报警。

对应 Commander 逻辑：

```cpp
set_tune(tune_control_s::TUNE_ID_ARMING_WARNING);
```

含义：

```text
飞控已经 armed，电机 / 舵机等执行器可能动作，需要注意安全。
```

它和故障报警不同：

- 解锁警示：`TUNE_ID_ARMING_WARNING`
- 错误音：`TUNE_ID_ERROR`
- 解锁失败音：`TUNE_ID_ARMING_FAILURE`
- 低电量警告：`TUNE_ID_BATTERY_WARNING_SLOW / FAST`
- GPS / 传感器类警告：`TUNE_ID_GPS_WARNING`

如果只是点击 QGC 解锁后响一次或响一段固定警示音，通常表示进入 armed 状态；如果持续急促响或伴随 QGC pre-arm / failsafe 提示，再结合 `commander status`、`listener vehicle_status`、`dmesg` 判断是否存在真实故障。

### 5. PX4 当前定义的声音种类

PX4 的声音 ID 定义在：

```text
msg/tune_control.msg
```

实际音符定义在：

```text
src/lib/tunes/tune_definition.desc
```

当前一共有 `20` 种 tune ID，编号 `0~19`：

| ID | 名称 | 代码含义 |
|---:|---|---|
| `0` | `STOP` | 停止播放 |
| `1` | `STARTUP` | 启动音 |
| `2` | `ERROR` | 错误音 |
| `3` | `NOTIFY_POSITIVE` | 正向提示音 |
| `4` | `NOTIFY_NEUTRAL` | 中性提示音 |
| `5` | `NOTIFY_NEGATIVE` | 负向提示音 |
| `6` | `ARMING_WARNING` | 解锁警示音 |
| `7` | `BATTERY_WARNING_SLOW` | 低电量慢警告 |
| `8` | `BATTERY_WARNING_FAST` | 严重低电量快警告 |
| `9` | `GPS_WARNING` | GPS / 传感器类警告 |
| `10` | `ARMING_FAILURE` | 解锁失败音 |
| `11` | `PARACHUTE_RELEASE` | 降落伞释放音 |
| `12` | `SINGLE_BEEP` | 单声提示 |
| `13` | `HOME_SET` | Home 点设置音 |
| `14` | `SD_INIT` | SD 初始化 / 格式化成功相关 |
| `15` | `SD_ERROR` | SD 错误 |
| `16` | `PROG_PX4IO` | PX4IO 编程中 |
| `17` | `PROG_PX4IO_OK` | PX4IO 编程成功 |
| `18` | `PROG_PX4IO_ERR` | PX4IO 编程失败 |
| `19` | `POWER_OFF` | 关机音 |

可以在 NSH 中手动试听：

```sh
tune_control play -t 1
tune_control play -t 6
tune_control play -t 10
```

其中：

- `-t 1`：启动音。
- `-t 6`：解锁警示音。
- `-t 10`：解锁失败音。

## 代码 / 流程

### 1. 启用 PX4 蜂鸣器驱动与命令

文件：

```text
boards/gjl/h743mini/default.px4board
```

修改：

```diff

```

意义：

- `CONFIG_SYSTEMCMDS_TUNE_CONTROL=y`：编译 `tune_control` 命令，方便 NSH 中手动测试蜂鸣器。

### 2. 映射 H743mini 蜂鸣器引脚

文件：

```text
boards/gjl/h743mini/src/board_config.h
```

原 V6C 遗留配置：

```c
#define TONE_ALARM_TIMER        3  /* Timer 3 */
#define TONE_ALARM_CHANNEL      3  /* PB0 GPIO_TIM3_CH3OUT_1 */

#define GPIO_BUZZER_1           /* PPB0 */ (GPIO_OUTPUT|GPIO_PUSHPULL|GPIO_SPEED_2MHz|GPIO_OUTPUT_CLEAR|GPIO_PORTB|GPIO_PIN0)

#define GPIO_TONE_ALARM_IDLE    GPIO_BUZZER_1
#define GPIO_TONE_ALARM         GPIO_TIM3_CH3OUT_1
```

改为 H743mini 当前规划：

```c
#define TONE_ALARM_TIMER        12  /* Timer 12 */
#define TONE_ALARM_CHANNEL      1   /* PB14 GPIO_TIM12_CH1OUT_1 */

#define GPIO_BUZZER_1           /* PB14 */ (GPIO_OUTPUT|GPIO_PUSHPULL|GPIO_SPEED_2MHz|GPIO_OUTPUT_CLEAR|GPIO_PORTB|GPIO_PIN14)

#define GPIO_TONE_ALARM_IDLE    GPIO_BUZZER_1
#define GPIO_TONE_ALARM         GPIO_TIM12_CH1OUT_1
```

### 3. 修复 STM32H7 APB1L TIMxEN 兼容

文件：

```text
platforms/nuttx/src/px4/stm/stm32_common/tone_alarm/ToneAlarmInterfacePWM.cpp
```

原来的逻辑把 `STM32_RCC_APB1ENR` 地址别名和 TIMxEN 位宏别名放在同一个条件中：

```c
#if !defined(STM32_RCC_APB1ENR) && defined(STM32_RCC_APB1LENR)
...
#endif
```

这会导致一种情况无法覆盖：

```text
STM32_RCC_APB1ENR 地址名已经存在
但 RCC_APB1ENR_TIM12EN 位宏不存在
```

本轮改为：

- 地址别名单独判断。
- 每个 TIMxEN 位宏单独判断，缺哪个补哪个。

关键补丁形态：

```c
#if !defined(RCC_APB1ENR_TIM12EN) && defined(RCC_APB1LENR_TIM12EN)
# define RCC_APB1ENR_TIM12EN RCC_APB1LENR_TIM12EN
#endif
```

## 常见坑

1. `tone_alarm` 关闭时，`Commander` 仍可能发布 `tune_control` 话题，但没有底层驱动把它变成声音。
2. `tune_control` 命令关闭时，NSH 里不能手动播放测试音。
3. 只打开 `tone_alarm`，但 `board_config.h` 仍指向旧的 `PB0 / TIM3_CH3`，会导致输出脚和当前硬件规划不一致。
4. STM32H7 的 RCC APB1 low register 命名和旧式 STM32 common 代码不完全一致，`TIM12EN` 这类位宏需要兼容别名。
5. `PB14` 是 3.3V MCU GPIO，不应直接接 5V 到引脚。
6. 无源压电片可用 3.3V PWM 做基础验证；5V 有源蜂鸣器或电磁蜂鸣器建议用三极管/MOS 管驱动。
