# 028 板级遗留外设裁剪与串口收口

时间：2026-07-07 09:25:33

## 任务目标

继承 `027 屏蔽 V6C 遗留电源 GPIO 冲突` 的后续整理方向，在 IMU 硬件尚未到位前，继续清理 H743mini 从 FMU-v6C 继承来的板级外设配置。

本阶段目标不是接入新传感器，而是把当前没有硬件基础、容易误导后续接线或占用固件空间的遗留项先收口：

- 不再默认初始化未确认的 CAN 引脚。
- 不再保留 SPI2 legacy flash / FRAM 路径。
- 将 GPS1 串口角色调整到规划中的 USART2 `PA2/PA3`。
- 标注 USART6 不再作为 PX4IO 使用，后续预留给 RCIN / CRSF。
- 关闭未确认 CAN transceiver 的 UAVCAN 驱动，降低固件体积。

## 任务背景

027 已经处理了 `PB2`、`PC10/PC11`、`PA15` 这些会和真实外设冲突的 V6C 电源 GPIO。本阶段继续处理“不会立刻导致冲突，但会影响后续外设接入判断”的继承项。

当前 H743mini 已确认的方向是：

- 存储：I2C2 EEPROM + QSPI GD25Q128，不再使用 SPI2 FRAM / SPI flash。
- GPS1：USART2 `PA2/PA3`。
- RCIN / CRSF：后续优先规划 USART6 `PC6/PC7`。
- CAN / UAVCAN：当前没有确认 CAN transceiver，不作为优先外设。
- IMU：ICM42688P 仍待硬件到位后再进入实际适配。

## 概念

### 板级裁剪和功能删除的区别

本阶段做的是“当前硬件阶段的裁剪”，不是永久否定这些功能。

- 关闭 UAVCAN：表示当前最小系统板没有确认 CAN 收发器，不把 UAVCAN 编进固件。
- 屏蔽 CAN GPIO 初始化：表示不在启动阶段把 `PD0/PD1/PB5/PB13` 配成 CAN。
- 保留 CAN 引脚定义：表示后续如果加 CAN transceiver，仍然可以恢复。
- 关闭 SPI2：表示当前存储链路已经转到 EEPROM + QSPI，不再保留 V6C legacy SPI2 flash / FRAM。

### 串口角色要和真实接线一致

PX4 的 `CONFIG_BOARD_SERIAL_GPS1`、`TELx` 等配置决定启动脚本和参数默认值如何理解串口用途。

本阶段将：

```text
GPS1 -> /dev/ttyS1
TEL3 -> disabled
```

用于匹配规划接线：

```text
USART2_TX PA2
USART2_RX PA3
```

否则会出现“编译通过但 GPS 驱动监听错串口”的问题。

## 本轮修改内容

### 1. CAN1 / CAN2 初始化屏蔽

在 `boards/gjl/h743mini/src/board_config.h` 中，CAN1 / CAN2 不再进入 `PX4_GPIO_INIT_LIST`。

保留内容：

- `GPIO_CAN1_RX/TX`
- `GPIO_CAN2_RX/TX`
- `board.h` 中的 CAN 引脚定义

屏蔽目的：

- 当前 CAN transceiver routing 未确认。
- 不在启动阶段错误初始化 CAN 引脚。
- 后续若确认硬件存在 CAN 收发器，可单独恢复。

### 2. SPI2 legacy flash / FRAM 路径清理

在 `boards/gjl/h743mini/src/spi.cpp` 中，`V6C00`、`V6C01`、`V6C21` 三套硬件版本里的 SPI2 flash 设备注册均已屏蔽：

```cpp
// H743mini does not use the inherited V6C SPI2 flash/FRAM path.
// Storage is provided by I2C2 EEPROM + QSPI GD25Q128.
// initSPIBus(SPI::Bus::SPI2, {
// 	initSPIDevice(SPIDEV_FLASH(0), SPI::CS{GPIO::PortD, GPIO::Pin4})
// }),
```

在 `boards/gjl/h743mini/nuttx-config/nsh/defconfig` 中关闭：

```text
# CONFIG_STM32H7_SPI2 is not set
# CONFIG_STM32H7_SPI2_DMA is not set
# CONFIG_STM32H7_SPI2_DMA_BUFFER is not set
```

在 `boards/gjl/h743mini/nuttx-config/include/board_dma_map.h` 中屏蔽：

```c
//#define DMAMAP_SPI2_RX    DMAMAP_DMA12_SPI2RX_0
//#define DMAMAP_SPI2_TX    DMAMAP_DMA12_SPI2TX_0
```

`board.h` 中的 `GPIO_SPI2_*` 暂时保留为候选定义，不主动初始化，不占脚。

### 3. GPS1 串口调整到 USART2

在 `boards/gjl/h743mini/default.px4board` 中：

```text
CONFIG_BOARD_SERIAL_GPS1="/dev/ttyS1"
# CONFIG_BOARD_SERIAL_TEL3 is not set
```

目的：

- `/dev/ttyS1` 对应当前规划的 USART2 `PA2/PA3`。
- 关闭 `TEL3`，避免它继续占用 `/dev/ttyS1`。
- 后续 GPS 接入时，GPS 驱动会优先使用规划串口。

### 4. USART6 从 PX4IO 语义中释放

`CONFIG_DRIVERS_PX4IO` 已经关闭，但代码中仍保留 `PX4IO_SERIAL_*` 相关定义。

本阶段不删除这些宏，只补充说明：

```text
CONFIG_DRIVERS_PX4IO is disabled on H743mini.
USART6 PC6/PC7 is reserved for later RCIN/CRSF planning.
```

同时将 `board_dma_map.h` 中 USART6 DMA 注释从 `PX4IO` 改为：

```text
USART6, future RCIN/CRSF
```

### 5. 关闭 UAVCAN

在 `boards/gjl/h743mini/default.px4board` 中：

```text
# H743mini CAN transceiver routing is not confirmed yet.
CONFIG_DRIVERS_UAVCAN=n
# CONFIG_BOARD_UAVCAN_TIMER_OVERRIDE is not set
```

原因：

- 当前板级 CAN transceiver routing 未确认。
- CAN GPIO 初始化已屏蔽。
- 继续编入 UAVCAN 会占用较多 flash，且当前没有对应硬件验证对象。

## 修改流程

1. 从 027 的“下一阶段任务”开始，先区分 V6C 遗留项是“真实引脚冲突”“运行时串口角色错误”还是“仅命名/注释残留”。
2. 先处理 CAN / USART2 / SPI2 的直接配置问题。
3. 再完整关闭 SPI2 legacy flash / FRAM 路径：设备表、NuttX SPI2 配置、DMA 映射三处一起收口。
4. 调整 GPS1 到 USART2，并关闭 TEL3 避免串口角色冲突。
5. 标注 USART6 不再作为 PX4IO 使用，保留给后续 RCIN / CRSF。
6. 确认当前不接 CAN transceiver 后，关闭 UAVCAN。
7. 多次执行 `make gjl_h743mini_default` 验证。
8. 构建中遇到 ROMFS 增量缓存导致的 airframe metadata 报错，清理 ROMFS 中间产物后重新构建通过。

## 当前结论

- V6C legacy SPI2 flash / FRAM 路径已不再参与当前固件。
- GPS1 已从旧的 `/dev/ttyS0` 调整到 USART2 对应的 `/dev/ttyS1`。
- TEL3 已关闭，避免和 GPS1 抢 `/dev/ttyS1`。
- USART6 仍保留底层使能，但语义上不再视为 active PX4IO，后续可作为 RCIN / CRSF 候选。
- CAN1 / CAN2 不再默认初始化。
- UAVCAN 已关闭，当前固件体积明显下降。
- 当前工作区干净，所有阶段改动均已提交。

## 常见坑

- `CONFIG_xxx is not set` 不是合法 Kconfig 写法，必须写成 `# CONFIG_xxx is not set`。
- `GPS1` 串口配置错误通常不会导致编译失败，而是运行时 GPS 驱动监听错串口。
- ROMFS 增量构建可能复用被裁剪过的 build 目录 airframe 文件，导致误报缺 `@type`；清理 ROMFS 中间产物后再构建。
- `board.h` 中保留 `GPIO_SPI2_*` 不等于 SPI2 仍被启用；关键要看 `defconfig`、`spi.cpp` 和 DMA 映射。
- 关闭 UAVCAN 不等于以后不能用 CAN；只是当前最小系统板没有确认 CAN transceiver，先不把它编进固件。

## 调试方法

后续上板验证可以按下面顺序：

1. 烧录最新 `.px4`。
2. 完全断电冷启动。
3. 检查基础链路：
   - QGC 是否连接。
   - NSH 是否可用。
   - `dmesg` 是否有新的启动异常。
4. 检查存储：
   - `mtd status`
   - `param save`
   - 重启后 `param show`
   - `mount` 确认 `/fs/microsd`
5. GPS 硬件接入后检查：
   - `gps status`
   - `listener sensor_gps 1`
6. 如果再次遇到 ROMFS `@type` 报错，先清理 build 目录下 ROMFS 中间产物，不要误改 airframe 源文件。

## 复盘要点

本阶段最大的收益不是新增功能，而是把最小系统板固件从完整 FMU-v6C 默认假设中继续剥离出来。

当前策略是：

```text
真实硬件已验证的保留
当前没有硬件基础的关闭
未来可能用到的保留定义但不初始化
会误导后续规划的注释改清楚
```

这样做之后，后续接 IMU、GPS、RCIN、PWM 时更容易判断每个引脚和串口是否真的空闲。

## 下一阶段任务和目标

目标：在存储、TF 卡、USB/QGC/NSH 和基础板级裁剪都稳定的基础上，进入真实外设适配前的最后准备阶段。

优先任务：

- `heater PB9` 暂时保持不动；若确认没有 IMU heater 电路，再单独屏蔽 `CONFIG_DRIVERS_HEATER` 和 `GPIO_HEATER_OUTPUT`。
- 等 `ICM42688P` 到位后，优先适配主 IMU：
  - 启用并重新整理 `spi.cpp` 里的 SPI2 设备表。
  - 将 ICM42688P 从 V6C 遗留 `SPI1/PC13` 迁移到 `SPI2 PC2/PC3/PD3 + PE4 CS + PE6 DRDY`。
  - 注意 `PD3` 在排针上对应 `P2-38`。
- GPS 硬件接入后，验证 `/dev/ttyS1` / USART2 `PA2/PA3` 是否能正常发布 `sensor_gps`。
- RCIN / CRSF 阶段再启用 USART6 对应的接收机驱动，不提前改功能。
- PWM 阶段再处理 `PA15/PB3/PB10/PB11` 与 `timer_config.cpp`、NuttX TIM2 配置。
- 低优先级整理 V6C 命名残留，例如 include guard、链接脚本注释、`V6C00/V6C01/V6C21` 命名说明；不要在外设适配前贸然改硬件版本 ID。

验收标准：

- `make gjl_h743mini_default` 持续通过。
- FLASH 使用率保持有余量。
- QSPI 参数存储、EEPROM MTD、TF 卡冷启动挂载不回归。
- GPS、IMU、RCIN、PWM 每进入一个阶段，都能明确旧用途、新用途、源码位置和上板验证命令。
