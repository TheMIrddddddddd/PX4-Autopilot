# 009 HOTPLUG 连接成功但 verify 用法错误 2026-06-27 12:17:50

## 概念
本次进展是确认 `mode=HOTPLUG` 可以稳定连接到 STM32H743 目标芯片。独立执行 `-v file address` 触发 CubeProgrammer 用法错误，说明当前版本要求 verify 跟在 write 命令之后执行。

## 代码/流程
### 已执行命令
```bash
STM32_Programmer_CLI -c port=SWD mode=HOTPLUG freq=1000 \
  -v build/gjl_h743mini_bootloader/gjl_h743mini_bootloader.bin 0x08000000
```

### 关键输出
```text
SWD freq    : 950 KHz
Connect mode: Hot Plug
Reset mode  : Software reset
Device ID   : 0x450
Device name : STM32H7xx
NVM size    : 2 MBytes

Error: Wrong verify command use: it must be performed just after write command or write 32-bit command
```

### 当前判断
- HOTPLUG 模式连接目标芯片成功。
- 当前错误不是 SWD 连接错误，也不是文件内容错误。
- CubeProgrammer v2.22.0 下，`-v` 应放在 `-w` 写入命令后面一起执行。

## 常见坑
- `-v file address` 这种单独校验形式在当前工具输出中不可用。
- 如果要校验，使用 `-w file address -v`。
- 如果 `mode=UR` 不稳定，后续烧录可优先使用 `mode=HOTPLUG freq=1000`。

## 调试方法
建议重新写入 bootloader 并立即校验：

```bash
STM32_Programmer_CLI -c port=SWD mode=HOTPLUG freq=1000 \
  -w build/gjl_h743mini_bootloader/gjl_h743mini_bootloader.bin 0x08000000 \
  -v
```

然后写入 app 并校验：

```bash
STM32_Programmer_CLI -c port=SWD mode=HOTPLUG freq=1000 \
  -w build/gjl_h743mini_default/gjl_h743mini_default.bin 0x08020000 \
  -v -rst
```

## 复盘要点
- HOTPLUG 是当前板子更稳定的连接方式。
- verify 需要跟随 write 命令执行。
- 下一步应重新写入 bootloader 并使用同一条命令完成 verify。
