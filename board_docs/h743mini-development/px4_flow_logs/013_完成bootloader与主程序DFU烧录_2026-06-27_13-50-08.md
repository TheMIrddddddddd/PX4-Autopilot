## 本次关键修改

### 1. 禁用错误的 PA9 USB VBUS 检测

你的板子上：

- PA9 是 USART1_TX，接 CH340。
- PA10 是 USART1_RX，接 CH340。
- 原生 USB 使用 PA11/PA12。
- 没有看到 VBUS 接到 PA9。

所以不能继续使用 V6C 的 PA9 VBUS 检测逻辑。否则 bootloader 或主程序可能会错误采样/配置 PA9，和 USART1 冲突。

已修改：

- `boards/gjl/h743mini/src/hw_config.h`
- `boards/gjl/h743mini/src/board_config.h`
- `boards/gjl/h743mini/src/usb.c`

核心思路：

```c
#define BOARD_USB_VBUS_SENSE_DISABLED  1
```

同时让 USB 初始化不再配置 `GPIO_OTGFS_VBUS`。

### 2. 修正 bootloader defconfig 指向

发现 bootloader 的 NuttX 配置仍然指向官方 V6C：

```text
CONFIG_ARCH_BOARD_CUSTOM_DIR="../../../../boards/px4/fmu-v6c/nuttx-config"
CONFIG_ARCH_CHIP_STM32H753II=y
```

这会导致 bootloader 继续使用官方 V6C/H753 板级配置，而不是当前 h743mini 的 25MHz HSE、USB、引脚配置。

已改为：

```text
CONFIG_ARCH_BOARD_CUSTOM_DIR="../../../../boards/gjl/h743mini/nuttx-config"
CONFIG_ARCH_CHIP_STM32H743II=y
```

文件：

- `boards/gjl/h743mini/nuttx-config/bootloader/defconfig`

### 3. 修正主程序芯片型号

你的芯片是 `STM32H743IIT6`，对应 NuttX 配置应使用 `STM32H743II`，不是 `STM32H743VI`。

已修改：

```text
CONFIG_ARCH_CHIP_STM32H743II=y
```

文件：

- `boards/gjl/h743mini/nuttx-config/nsh/defconfig`

## 烧录流程

### 1. 进入 STM32 ROM DFU

操作：

1. 按住 `BOOT0`。
2. 点按 `RST/NRST`。
3. 保持 `BOOT0`。

主机识别为：

```text
0483:df11 STMicroelectronics STM Device in DFU Mode
Device Index: USB1
Device ID: 0x0450
```

### 2. 烧录 bootloader 到 0x08000000

命令：

```bash
STM32_Programmer_CLI -c port=USB1 \
  -w build/gjl_h743mini_bootloader/gjl_h743mini_bootloader.bin 0x08000000 \
  -v
```

结果：

```text
File download complete
Download verified successfully
```

### 3. 验证 PX4 bootloader USB 枚举

松开 `BOOT0`，按 `RST`。

主机识别为：

```text
3185:0038 Auterion PX4 BL FMU v6C.x
/dev/ttyACM0
```

这说明 bootloader 已经运行，并且原生 USB CDC 枚举成功。

### 4. PX4 uploader 未完成握手

尝试：

```bash
python3 -u Tools/px_uploader.py \
  --port /dev/ttyACM0 \
  build/gjl_h743mini_default/gjl_h743mini_default.px4
```

现象：

```text
Loaded firmware for board id: 56,0 size: 1855336 bytes (94.37%), waiting for the bootloader...
```

结论：

- USB CDC 枚举已经成功。
- 但 PX4 uploader 协议握手没有成功。
- 本阶段不继续卡在 uploader，先通过 ROM DFU 直接烧主程序，保证主程序先跑起来。

已临时停止 ModemManager：

```bash
echo 0 | sudo -S systemctl stop ModemManager
```

### 5. 烧录主程序到 0x08020000

重新进入 STM32 ROM DFU 后执行：

```bash
STM32_Programmer_CLI -c port=USB1 \
  -w build/gjl_h743mini_default/gjl_h743mini_default.bin 0x08020000 \
  -v
```

结果：

```text
File: gjl_h743mini_default.bin
Size: 1.77 MB
Address: 0x08020000
Erasing internal memory sectors [1 15]
Download verified successfully
```

含义：

- sector0 保留给 bootloader。
- sectors `[1 15]` 写入主程序。
- `0x08020000` 是当前 PX4 app 的链接地址。

## 为什么本阶段这样做

这次问题不是单纯“bootloader 没写进去”，而是：

1. 早期 bootloader 配置仍然沿用官方 V6C/H753。
2. 你的硬件是 H743IIT6，HSE 是 25MHz。
3. 你的 PA9 是 USART1_TX，不是 USB VBUS。
4. ROM DFU 能枚举，证明 PA11/PA12 USB 硬件通路是通的。
5. 修正 bootloader 板级配置后，PX4 bootloader 能枚举为 `/dev/ttyACM0`。
6. uploader 协议暂未握手成功，所以先用 ROM DFU 直接烧主程序验证启动。

## 下一步建议

下一阶段先验证运行状态：

1. 用 `/dev/ttyACM0` 尝试 QGroundControl 或 MAVLink 连接。
2. 或使用串口工具连接 CH340 的 USART1，确认是否能看到 NSH/启动日志。
3. 如果 PX4 主程序启动但报大量传感器错误，先不要急着加外设，先看 `dmesg` 和启动脚本。
4. 后续再单独排查 `px_uploader.py` 为什么对当前 bootloader 只枚举、不握手。
5. 阶段稳定后提交 Git，注意不要提交 `.vscode/settings.json`。
