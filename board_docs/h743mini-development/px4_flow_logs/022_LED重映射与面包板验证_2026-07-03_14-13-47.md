### 本轮概念澄清

`EVENTOUT`：

- STM32 的特殊复用功能，可把 MCU 内部事件输出到引脚。
- 当前 PX4 板级规划基本不用。
- `PI8/PI11` 等脚即使 pinmap 中显示 `EVENTOUT`，只要配置为普通 GPIO，就不会进入 `EVENTOUT` 模式。

`USB HS ULPI`：

- 是 USB High Speed 外接 PHY 的并行接口。
- 当前 H743mini 第一阶段只使用 USB FS 的 `PA11/PA12`，不规划 USB HS ULPI。

蜂鸣器：

- PX4 原 V6C 风格更适合接无源蜂鸣器或压电片。
- `tone_alarm` 通过定时器输出不同频率的音调。
- 本轮已规划 `PB14 / TIM12_CH1`。

`HEATER_OUTPUT`：

- 是给 IMU / 传感器恒温加热使用的控制输出。
- 目标是让传感器处在更稳定的温度区间，减少温漂。
- 当前最小系统板阶段先不做传感器恒温。

`FRAM / EEPROM / MTD`：

- 都属于非易失存储相关概念。
- PX4 可用这些存储参数、航点、校准数据、硬件 ID 等。
- 当前 `gjl/h743mini` 仍保留 V6C 的 FRAM/EEPROM/MTD 假设，后续需要决定是增加外部存储硬件并适配，还是关闭/替换这些默认假设。

## 概念

本轮区分了三类容易混淆的 LED 控制方式：

```text
普通 GPIO 状态灯
  -> /dev/led0
  -> boards/gjl/h743mini/src/led.c
  -> stm32_gpiowrite()

PX4 Commander 状态灯逻辑
  -> 根据 armed / ready / failsafe / overload 状态周期性 toggle
  -> 通过 BOARD_ARMED_STATE_LED / BOARD_ARMED_LED / BOARD_OVERLOAD_LED 选择逻辑灯

RGBLED / lights 驱动
  -> led_control uORB
  -> rgbled / rgbled_pwm / neopixel / UAVCAN rgbled 等驱动
  -> 不适合本轮三颗普通 GPIO LED 的第一阶段验证
```

当前采用的是普通 GPIO LED 方案，不使用 `rgbled`、`rgbled_pwm`、`neopixel` 等 RGB 灯驱动。

LED 硬件接法采用低电平点亮：

```text
3.3V -> 限流电阻 -> LED 正极
LED 负极 -> STM32 GPIO
```

当 GPIO 输出低电平时，电流从 `3.3V` 经电阻和 LED 流入 GPIO，LED 点亮；当 GPIO 输出高电平时，LED 两端接近同电位，LED 熄灭。

GPIO 电气能力结论：

- `PI11` 作为普通 I/O，优先给错误灯或需要更明显状态提示的红灯。
- `PI8` 和 `PC13` 在 STM32H743 datasheet 中属于更保守的特殊 I/O 电流能力组，适合小电流状态灯。
- 三路 LED 都必须串联限流电阻，不能直接裸接 LED。

## 代码/流程

### board_config.h

文件：

```text
boards/gjl/h743mini/src/board_config.h
```

LED GPIO 从旧 `PB0/PB1` 改为：

```c
#define GPIO_nLED_RED        /* PI11 */  (GPIO_OUTPUT|GPIO_PUSHPULL|GPIO_SPEED_2MHz|GPIO_OUTPUT_SET|GPIO_PORTI|GPIO_PIN11)
#define GPIO_nLED_BLUE       /* PI8  */  (GPIO_OUTPUT|GPIO_PUSHPULL|GPIO_SPEED_2MHz|GPIO_OUTPUT_SET|GPIO_PORTI|GPIO_PIN8)
#define GPIO_nLED_GREEN      /* PC13  */  (GPIO_OUTPUT|GPIO_PUSHPULL|GPIO_SPEED_2MHz|GPIO_OUTPUT_SET|GPIO_PORTC|GPIO_PIN13)

#define BOARD_HAS_CONTROL_STATUS_LEDS      1
#define BOARD_OVERLOAD_LED     LED_RED
#define BOARD_ARMED_STATE_LED  LED_BLUE
#define BOARD_ARMED_LED        LED_GREEN
```

说明：

- `GPIO_OUTPUT_SET` 对低电平点亮 LED 来说表示默认灭灯。
- `GPIO_SPEED_2MHz` 足够用于状态灯，不需要沿用旧的 `GPIO_SPEED_50MHz`。
- `BOARD_ARMED_LED` 新增为 `LED_GREEN`，让 Commander 能在解锁后控制绿灯常亮。

## 常见坑

- 不要把 LED 负极接到 `3.3V`。当前低电平点亮接法是 LED 正极经电阻接 `3.3V`，LED 负极接 GPIO。
- 不要不串电阻直接接 LED，容易烧 LED 或损伤 GPIO。
- 不要用 `led_control` 命令直接判断普通 GPIO LED 是否正常；`led_control` 走的是 uORB / lights 驱动链路，不等于 `/dev/led0` 普通 GPIO 状态灯。
- 不要把绿灯不亮误判为 `PC13` 故障。绿灯现在表示 armed 常亮，飞控没有解锁时应当熄灭。
- 不要把临时 `usleep()` 自检代码长期留在 `init.c`，否则会固定增加启动延时。
- 不要改 `boards/px4/fmu-v6c` 原板文件，当前适配应只改 `boards/gjl/h743mini`。
- 不要忘记 bootloader 与 default 固件是两套阶段；`make gjl_h743mini_default upload` 不会自动更新已经烧进去的 bootloader。

## 调试方法

LED 调试建议分三层：

1. 硬件层：
   - 检查 LED 正负极。
   - 检查限流电阻是否串联。
   - 检查 `3.3V`、GPIO、面包板接触是否可靠。

2. GPIO 层：
   - 临时在 `init.c` 用 `led_on()` / `led_off()` 做短时间自检。
   - 自检完成后删除临时代码。

3. PX4 状态层：
   - 通过 Commander 状态观察蓝灯和绿灯。
   - 通过错误 / overload 条件观察红灯。
   - 注意当前 IMU、气压计等还没完整适配时，飞控可能不能进入 ready-to-arm 或 armed。

建议后续如果要重新验证 LED：

```text
先确认面包板限流电阻
  -> 烧录 default 固件
  -> 看启动阶段是否没有异常红灯
  -> 看蓝灯是否按 not-ready 状态闪烁
```
