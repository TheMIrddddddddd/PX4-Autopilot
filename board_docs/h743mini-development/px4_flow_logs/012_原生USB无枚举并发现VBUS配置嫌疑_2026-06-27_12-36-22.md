# 012 原生 USB 无枚举并发现 VBUS 配置嫌疑 2026-06-27 12:36:22

## 概念
本次任务是直接测试 STM32H743 最小系统板 PA11/PA12 原生 USB 是否能枚举 PX4 bootloader。测试结果是 Linux 未看到 `/dev/ttyACM*` 或 PX4 bootloader 相关 USB 设备，说明当前 USB bootloader 尚未正常枚举。

## 代码/流程
### 已执行检查
```bash
ls -l /dev/ttyACM* /dev/ttyUSB* /dev/serial/by-id/* 2>/dev/null
lsusb
sudo dmesg --ctime | tail -n 100
timeout 20 udevadm monitor --kernel --subsystem-match=usb --subsystem-match=tty
```

### 关键输出
- 当前没有看到 `/dev/ttyACM*`。
- 20 秒 `udevadm monitor` 未收到 USB/TTY 新事件。
- `dmesg` 只看到过 ST-Link 和 CH340：

```text
Product: STM32 STLink
Product: USB Serial
ch341-uart converter now attached to ttyUSB0
```

没有看到 PX4 bootloader、STM32 CDC ACM 或新的 `/dev/ttyACM0` 枚举。

### 代码检查发现
当前 PX4 bootloader 配置中：

```c
#define INTERFACE_USB                  1
#define INTERFACE_USB_CONFIG           "/dev/ttyACM0"
#define BOARD_VBUS                     MK_GPIO_INPUT(GPIO_OTGFS_VBUS)
```

当前 VBUS 引脚定义来自 V6C：

```c
#define GPIO_OTGFS_VBUS /* PA9 */ ...
```

但当前最小系统板硬件中：

```text
PA9 = USART1_TX，连接 CH340
PA10 = USART1_RX，连接 CH340
PA11/PA12 = 原生 USB FS
```

因此 `BOARD_VBUS` 使用 PA9 很可能和当前硬件冲突。

### 当前判断
- 物理上用户连接的是 PA11/PA12 原生 USB 口。
- Linux 没有看到 USB 枚举，说明 PX4 bootloader 的 USB CDC 设备没有起来。
- 一个高优先级嫌疑是 bootloader 仍按 V6C 使用 PA9 做 VBUS 检测，而当前板 PA9 已被 USART1_TX 占用。

## 常见坑
- PA11/PA12 是 USB D-/D+，但很多 STM32 USB 方案还会使用 PA9 做 VBUS sensing。
- 当前板 PA9 同时被设为 USART1_TX 和 USB VBUS sensing 会产生配置冲突。
- 没有 `/dev/ttyACM0` 时，`px_uploader.py --port /dev/ttyACM0` 不可能成功。

## 调试方法
下一步有两条路线：

### 路线 A：修改 PX4 bootloader 配置
修改自定义 board 的 bootloader 配置，去掉对 PA9 VBUS 的依赖，让 bootloader 不再用 PA9 判断 USB 是否连接。

候选修改点：

```text
boards/gjl/h743mini/src/hw_config.h
boards/gjl/h743mini/src/usb.c
```

修改后重新：

```bash
make gjl_h743mini_bootloader
```

再重新烧 bootloader。

### 路线 B：使用 STM32 系统 Bootloader DFU
按住 BOOT0 进入 STM32 ROM bootloader，再测试 Linux 是否识别 DFU：

```bash
STM32_Programmer_CLI -l
```

如果出现 DFU Interface，可用 STM32CubeProgrammer 通过 DFU 写入 flash，绕开当前 SWD 连接不稳定问题。

## 复盘要点
- 原生 USB 当前没有枚举。
- 不能直接继续执行 PX4 USB 上传。
- 下一步应优先解决 bootloader 的 USB VBUS/PA9 配置冲突，或者走 STM32 ROM DFU 作为备用烧录路径。
