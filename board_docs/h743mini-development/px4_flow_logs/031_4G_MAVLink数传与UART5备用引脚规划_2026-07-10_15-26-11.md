## 关键结论

### 1. UART4 必须继续留给 JY901B

主日志已经确定：

```text
PH13 / UART4_TX / P1-50
PH14 / UART4_RX / P2-50
```

因此不能为了 4G 数传迁移或取消 JY901B。UART4 规划保持不变。

### 2. UART5 的 PC12/PD2 复用组不能使用

当前 `board.h` 沿用 FMUv6C 的 UART5 引脚：

```text
UART5_TX -> PC12
UART5_RX -> PD2
```

但当前 H743mini 的 TF 卡实际使用 SDMMC1：

```text
PC12 -> SDMMC1_CLK
PD2  -> SDMMC1_CMD
```

当前代码已经启用 SDMMC1，并在启动路径中初始化 TF 卡。直接恢复这组 UART5 复用会破坏 TF 卡、`logger` 和 `dataman` 链路，属于功能性冲突。

### 3. UART5 改用 PB13/PB12

STM32H743 NuttX pinmap 提供另一组 UART5 复用：

```text
GPIO_UART5_TX_1 -> PB13
GPIO_UART5_RX_1 -> PB12
```

排针图确认：

```text
PB13 -> P1-33
PB12 -> P1-32
```

最终接线规划：

| 4G DTU 信号 | 飞控引脚 | STM32 外设 | 排针 | 方向 |
|---|---|---|---|---|
| `RXD` | `PB13` | `UART5_TX` | `P1-33` | 飞控发送到 DTU |
| `TXD` | `PB12` | `UART5_RX` | `P1-32` | DTU 发送到飞控 |
| `GND` | `GND` | 共地 | 就近 GND | 双方共地 |
| `VIN` | 独立稳压电源 | 电源 | 按模块手册 | 不由 GPIO 供电 |

这组引脚不会占用 JY901B、GPS、CRSF、TF 卡、PWM、CURRENT 或 VOLTAGE。

## PB12/PB13 当前遗留用途

### PB12

当前 `board_config.h` 仍有：

```text
PB12 -> GPIO_nPOWER_IN_B -> Brick2 valid
```

它来自 FMUv6C 双路 Brick 电源检测假设。当前 H743mini 没有规划完整的双路 Brick valid 电路，主日志的电源检测使用 `PC4/PC5` 作为 CURRENT/VOLTAGE，因此后续启用 UART5 时需要：

- 从 `PX4_GPIO_INIT_LIST` 移除 `GPIO_nPOWER_IN_B`。
- 不再读取 `BOARD_ADC_BRICK2_VALID` 的 PB12 状态。
- 按当前真实硬件收口 `BOARD_NUMBER_BRICKS` 或第二路 Brick 有效状态。

### PB13

当前 `board.h` 仍有：

```text
PB13 -> GPIO_CAN2_TX
```

但当前：

```text
CONFIG_DRIVERS_UAVCAN=n
```

CAN1/CAN2 收发器路由也没有确认，CAN 引脚未进入当前初始化列表。因此 PB13 可以规划为 UART5_TX；启用 UART5 后不再把 PB13 恢复为 CAN2_TX。

## CURRENT/VOLTAGE 与 UART5 的关系

当前电池模拟量规划：

```text
CURRENT -> PC4 / P1-19 / ADC1_INP4
VOLTAGE -> PC5 / P1-20 / ADC1_INP8
```

UART5 使用：

```text
TX -> PB13 / P1-33
RX -> PB12 / P1-32
```

两组 GPIO 完全不同，没有引脚复用冲突。

当前电池功能仍有软件阻塞：

- `board_adc` 尚未启用。
- `battery_status` 尚未启用。
- `ADC_BATTERY1_VOLTAGE_CHANNEL` 虽然定义为 PC5，但当前 `ADC_CHANNELS` 掩码还没有包含该电压通道。
- PC4/PC5 只能接电源模块缩放后的 0~3.3V 模拟量，禁止直接接电池正极。

## UART 资源最终规划

| 外设 | STM32 串口 | GPIO | 用途 |
|---|---|---|---|
| CH340/NSH | USART1 | PA9/PA10 | 调试控制台 |
| GPS1 | USART2 | PA2/PA3 | GPS 收发 |
| JY901B | UART4 | PH13/PH14 | 副传感器串口 |
| 4G DTU | UART5 | PB13/PB12 | MAVLink/TEL2 |
| RCIN/CRSF | USART6 | PC6/PC7 | 遥控输入与遥测回传 |

TF 卡继续独占 `PC8~PC12/PD2`，不再把 `PC12/PD2` 作为 UART5。

## 最终 ttyS 设备号规划

当前 NuttX 启用了 `CONFIG_STM32H7_SERIAL_DISABLE_REORDERING`，但注册时仍会跳过未启用的 UART。因此设备号取决于最终启用的串口集合。

在同时启用 UART4 和 UART5 的最终目标状态下，预计为：

```text
USART1 -> /dev/ttyS0  CH340/NSH
USART2 -> /dev/ttyS1  GPS1
USART3 -> /dev/ttyS2  当前未分配
UART4  -> /dev/ttyS3  JY901B
UART5  -> /dev/ttyS4  4G MAVLink / TEL2
USART6 -> /dev/ttyS5  RCIN/CRSF
UART7  -> /dev/ttyS6
UART8  -> /dev/ttyS7
```

因此不能根据“只启用 UART5”的临时状态把 UART5 固定写成 `/dev/ttyS3`。最终值必须通过以下两项确认：

```text
build/gjl_h743mini_default/etc/init.d/rc.serial_port
板上 /dev/ttyS* 实际设备
```

## MAVLink 参数规划

第一版建议参数：

```text
MAV_1_CONFIG=102       # TEL2
MAV_1_MODE=0           # Normal，面向 QGC
MAV_1_FLOW_CTRL=0      # 两线 DTU，不使用 RTS/CTS
MAV_1_RADIO_CTL=0      # 普通 DTU 不发送 RADIO_STATUS
SER_TEL2_BAUD=115200
MAV_1_RATE=5000~8000
```

57600 可以传基础遥测，但参数读取会偏慢。第一阶段从 115200 开始，再根据 DTU 的持续吞吐、打包延迟和丢包情况调整 `MAV_1_RATE`。

## 4G 与服务器链路规划

```text
UART5 PB13/PB12
  -> 4G DTU UDP Client
  -> 公网服务器 UDP 14560
  -> UDP relay
  -> QGC UDP 14550
```

relay 需要具备：

- 学习并保存 DTU 和 QGC 两端的实际 UDP 源 IP/端口。
- 处理运营商 NAT、端点超时和断线重连。
- 双向透明转发 MAVLink 二进制数据。
- 不向 UART 数据流插入注册文本、心跳字符串、JSON 或 Modbus 模板。
- 限制允许访问的来源，避免公网任意主机注入 MAVLink 命令。

裸公网 UDP MAVLink 没有天然加密和认证。正式远程控制应增加 VPN、加密隧道或应用层鉴权，随机端口不能替代安全措施。

## 硬件风险

1. 4G 模块的 VIN 供电范围不等于 UART IO 电平；必须确认模块 TXD 对 STM32H743 的 3.3V IO 安全。
2. 4G 发射存在瞬时电流需求，应单独设计稳压、去耦和峰值电流余量，并与飞控共地。
3. UART5 使用 PB13/PB12 后，不能再把这两脚恢复为 CAN2_TX 或 Brick2 valid。
4. 两线 UART 不使用 RTS/CTS，必须关闭 MAVLink 硬件流控。
5. QGC 参数读取、任务上传和命令 ACK 都要求真正双向链路，不能只验证飞控单向发心跳。

## 当前结论

- 4G 数传可以在不改变主 MD 既有必要引脚的前提下实现。
- JY901B 继续使用 UART4 `PH13/PH14`。
- 4G DTU 使用 UART5 `PB13/PB12`。
- TF 卡继续使用 SDMMC1 `PC8~PC12/PD2`。
- CURRENT/VOLTAGE 继续使用 `PC4/PC5`。
- 当前只完成文档和引脚规划，尚未修改源码、编译、烧录或上板验证。

## 调试方法

后续实现后按以下顺序验证：

1. 构建后检查 `rc.serial_port`，确认 UART4/UART5/USART6 的最终设备号。
2. 完全断电冷启动，确认 TF 卡仍能挂载，`logger` 和 `dataman` 不受影响。
3. 使用 USB-TTL 对 PB13/PB12 做 UART5 双向收发测试。
4. 在 TEL2 上检查 `mavlink status`，确认有独立 MAVLink 实例。
5. QGC 通过 USB-TTL 链路读取完整参数并发送一条需要 ACK 的命令。
6. 接入 DTU，在局域或公网 relay 上检查双向 UDP 数据。
7. 验证断网、换 IP、DTU 重连和服务器重启后的恢复行为。
