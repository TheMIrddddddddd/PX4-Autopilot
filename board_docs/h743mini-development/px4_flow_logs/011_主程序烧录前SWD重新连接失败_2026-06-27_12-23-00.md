# 011 主程序烧录前 SWD 重新连接失败 2026-06-27 12:23:00

## 概念
本次任务是尝试由 AI 执行 PX4 主程序 app 烧录到 `0x08020000`。实际结果是写入尚未开始，CubeProgrammer 在重新连接目标芯片阶段无法读取 core ID。

## 代码/流程
### 已尝试命令
```bash
STM32_Programmer_CLI -c port=SWD mode=HOTPLUG freq=1000 \
  -w build/gjl_h743mini_default/gjl_h743mini_default.bin 0x08020000 \
  -v -rst
```

随后尝试：

```bash
STM32_Programmer_CLI -c port=SWD mode=UR reset=HWrst freq=1000

STM32_Programmer_CLI -c port=SWD mode=UR reset=HWrst freq=1000 \
  -w build/gjl_h743mini_default/gjl_h743mini_default.bin 0x08020000

STM32_Programmer_CLI -c port=SWD mode=UR reset=HWrst freq=100
```

### 关键输出
```text
Voltage     : 3.27V
Error: Unable to get core ID
Error: ST-LINK error (DEV_TARGET_CMD_ERR)
```

或：

```text
Error: ST-LINK error (DEV_CONNECT_ERR)
```

### 当前判断
- app 主程序尚未写入 `0x08020000`。
- bootloader 已在上一阶段成功写入并校验。
- 当前问题发生在 ST-Link 重新连接目标芯片阶段，不是 app bin 文件问题。
- 需要通过物理复位、断电重上电、检查 NRST 线等方式恢复稳定 SWD 连接。

## 常见坑
- bootloader 写入成功后，目标芯片开始运行 bootloader，SWD 连接时序可能比空片阶段更挑。
- 如果 NRST 没接牢，`mode=UR reset=HWrst` 不一定能真正控制 MCU reset。
- 目标电压正常只能说明供电存在，不代表 SWDIO/SWCLK/NRST 接触稳定。

## 调试方法
下一步建议：

1. 保持 BOOT0 低电平，不要按 BOOT0。
2. 断开板子电源，等待 3 秒后重新上电。
3. 确认 ST-Link 的 NRST 接到板子 NRST/RST。
4. 执行连接测试：

```bash
STM32_Programmer_CLI -c port=SWD mode=UR reset=HWrst freq=1000
```

如果仍失败，手动按住 RST，再执行：

```bash
STM32_Programmer_CLI -c port=SWD mode=UR reset=HWrst freq=1000
```

连接恢复后再烧 app：

```bash
STM32_Programmer_CLI -c port=SWD mode=UR reset=HWrst freq=1000 \
  -w build/gjl_h743mini_default/gjl_h743mini_default.bin 0x08020000 \
  -v -rst
```

## 复盘要点
- bootloader 已成功。
- app 尚未成功烧录。
- 当前阻塞点是 SWD 重新连接稳定性，优先检查 reset 和物理连接。
