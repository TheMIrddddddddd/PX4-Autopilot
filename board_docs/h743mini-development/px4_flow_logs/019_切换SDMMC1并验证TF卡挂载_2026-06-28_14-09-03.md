# 019 切换 SDMMC1 并验证 TF 卡挂载

时间：2026-06-28 14:09:03 CST

## 任务目标

## 本轮修改内容

根据用户提供的 TF CARD 原理图片段，确认板载 TF 卡连接为：

```text
SDIO_D0   PC8
SDIO_D1   PC9
SDIO_D2   PC10
SDIO_D3   PC11
SDIO_CLK  PC12
SDIO_CMD  PD2
```

这组引脚对应 STM32H743 的 `SDMMC1`，不是此前 V6C 模板中的 `SDMMC2`。

已修改：

```text
boards/gjl/h743mini/nuttx-config/nsh/defconfig
```

从：

```text
CONFIG_STM32H7_SDMMC2=y
```

改为：

```text
CONFIG_STM32H7_SDMMC1=y
# CONFIG_STM32H7_SDMMC2 is not set
```

已修改：

```text
boards/gjl/h743mini/nuttx-config/include/board.h
```

将原 V6C 的 SDMMC2 注释和 SDMMC2 remap 宏清理掉，保留 SDMMC1/SDIO 原理图对应说明：

```text
SDIO_D0   PC8
SDIO_D1   PC9
SDIO_D2   PC10
SDIO_D3   PC11
SDIO_CLK  PC12
SDIO_CMD  PD2
```

未在 `board.h` 里重新定义 `GPIO_SDMMC1_*`，因为 NuttX 芯片级 pinmap 已经在 `platforms/nuttx/NuttX/nuttx/arch/arm/src/stm32h7/hardware/stm32h7x3xx_pinmap.h` 中定义：

```text
GPIO_SDMMC1_D0   PC8
GPIO_SDMMC1_D1   PC9
GPIO_SDMMC1_D2   PC10
GPIO_SDMMC1_D3   PC11
GPIO_SDMMC1_CK   PC12
GPIO_SDMMC1_CMD  PD2
```

## 修改流程

1. 最初从当前代码读到 V6C 模板仍使用 SDMMC2：

```text
SDMMC2_CK   PD6
SDMMC2_CMD  PD7
SDMMC2_D0   PB14
SDMMC2_D1   PB15
SDMMC2_D2   PB3
SDMMC2_D3   PB4
```

2. 用户提供 TF CARD 原理图片段后，确认实际硬件是 SDMMC1 标准 SDIO 引脚。

3. 将 TF 卡从旧 K230/Canaan Buildroot 系统卡格式清空，重新格式化为整卡 FAT32，Linux 侧识别结果为：

```text
/dev/sda
FSTYPE: vfat
FSVER: FAT32
LABEL: PX4SD
UUID: 48AA-5A34
```

4. 用户自行完成编译和上板验证。本轮 AI 未负责编译。

5. 上板后通过 NSH 检查 `/dev`、`mount`、`/fs/microsd` 和 `dmesg`。

## 当前结论

TF 卡链路已经进入可用状态：

- `CONFIG_STM32H7_SDMMC1=y` 与硬件原理图匹配。
- `/dev/mmcsd0` 已出现。
- `/fs/microsd type vfat` 已挂载成功。
- `dataman` 已能在 `/fs/microsd/dataman` 上工作。
- `logger` 已能创建 `/fs/microsd/log`。
- 此阶段不再优先怀疑 SDMMC 引脚或 TF 卡格式。

当前仍存在的问题不属于 TF 卡挂载本身：

- `PX4_MTD` 仍按 V6C 的 FRAM/EEPROM 配置启动，当前硬件未适配。
- 新 FAT32 卡初次启动没有 `/fs/microsd/params`，因此出现一次 `param import failed`，可先执行 `param save` 后重启验证。
- `rc.board_defaults` 仍设置当前固件不存在的 `BAT*` 和 `MAV_2_*` 参数。
- `rc.board_sensors` 仍启动 V6C 默认 BMI055、ICM42688P、MS5611、IST8310。
- `GPS_1_CONFIG=201` 仍会启动 GPS1 并占用 `/dev/ttyS0`。
- H7 架构默认仍会启用 UAVCAN。

## 下一阶段任务和目标

下一阶段目标：在保留 TF 卡、USB/QGC、NSH 可用的前提下，继续清理 V6C 默认启动项，让 H743mini 最小系统日志更干净。

优先任务：

- 在 NSH 中执行 `param save`，重启后确认 `/fs/microsd/params` 是否生成，`param import failed` 是否消失。
- 处理 `PX4_MTD`：当前阶段可先关闭或清理不匹配的 V6C FRAM/EEPROM MTD manifest，后续再按真实 2 KB EEPROM 或外部 Flash 重新适配。
- 清理 `rc.board_defaults` 中当前固件不存在的 `BAT*` 和 `MAV_2_*` 默认参数。
- 暂停未接入的 V6C 默认传感器启动项。
- 关闭 GPS1 对 `/dev/ttyS0` 的占用，保留 USART1 作为 CH340/NSH 控制台。
- 关闭当前未使用的 UAVCAN 默认启动。

验收标准：

- 上电后 `mount` 仍显示 `/fs/microsd type vfat`。
- `dataman` 和 `logger` 继续可用。
- `dmesg` 不再出现 TF 卡挂载失败、dataman 打不开文件、Missing FMU SD Card。
- 清理后 V6C 默认外设报错数量明显减少。
